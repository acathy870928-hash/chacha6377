## 설계의 핵심 3가지

### 1. 프롬프트는 컴플라이언스를 보장하지 못한다

LLM은 프롬프트 지시를 확률적으로 위반합니다. 보험 권유 영역에서는 1회 위반도 민원이 됩니다.
그래서 **3중 가드레일**을 둡니다.

```
입력 필터 → 시스템 프롬프트 → 생성 → 출력 필터 → 근거 검증 → 고지 검증
```

`output_filter.py`가 4~6단계를 담당합니다. 실제로 이 필터의 자체 검증이 초기 정규식의 구멍 6건을 잡아냈습니다.

### 2. 숫자는 프롬프트가 아니라 데이터에 둔다

노후 적정생활비, 평균 수령액, 세액공제율은 매년 바뀝니다.
프롬프트에 하드코딩하면 갱신 누락이 곧 허위 안내가 됩니다.

`statistics.yaml`의 모든 항목에는 `source_org` / `base_year` / `verified_at` / `expires_at`이 붙어 있고,
`validate_assets.py`가 만료 항목을 배포 전에 잡아냅니다.

### 3. 단점을 먼저 말하는 것이 전환율을 높인다

세액공제 16.5%를 안내하면서 중도해지 기타소득세 16.5%를 빠뜨리면 설명의무 위반입니다.
동시에, 장점만 나열하는 챗봇은 고객이 이미 아는 리스크를 감추는 것으로 읽혀 신뢰를 잃습니다.

이 원칙은 페르소나 P1, 필수고지 DISC-007, 계산 함수 `calc_early_withdrawal_loss`,
평가 루브릭 T5·C3에 각각 구현되어 있습니다.

## 배포 전 체크리스트

```
□ 상품 데이터를 실제 판매 상품으로 교체 (product-schema.json)
□ statistics.yaml / tax-rules.yaml 준법감시인 검수 → compliance_approved: true
□ forbidden-expressions.json / required-disclosures.json 준법 승인
□ FAQ 40선 준법 검수
□ get_statistic / get_tax_rule / search_product_kb 구현
□ 상담 예약·핸드오프 시스템 연동
□ 레드팀 40건 방어율 100% (CRITICAL 기준)
□ 골든 데이터셋 평균 75점 이상
□ 출력 필터 오탐률 5% 이하
□ 개인정보 처리방침 · 마케팅 동의 분리 절차 검토
□ 준법감시인 최종 승인
```
