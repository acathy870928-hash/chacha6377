# Insurance AI

보험 상담 AI (BETA) — **신규 서비스**다. 데스크톱 웹 상담 화면이 기준이다.
기존 Orca AI(iFA Ai Link)의 확장이 아니며, 시장 리서치 위에서 새로 만든다.
파이썬 패키지명 `orca`는 작업 초기 코드명이며 제품명이 아니다.

## 무엇을 대체하는가

FA가 **선배 설계사 · 지점장에게 확인하던 것**을 대체한다.
24시간, 같은 기준으로, 조항 근거와 함께 답한다. 제품 정의는 `docs/product.md`.

시작 범위는 **Micky(보험 일반지식) + 약관** 두 소스뿐이며,
보장분석은 초개인화(「얼마 받을 수 있어요」) 단계에서 붙는다.

## 무엇이 다른가

약관을 검색해 주는 AI는 이미 있다(모홈 AI 등, `docs/market.md`).
이 서비스는 **「이 고객의 이 계약」으로 답하고, 그 답이 고객 폴더에 쌓인다.**

1. **계약 시점의 약관 판(edition)으로 답한다** — 보상은 최신 약관이 아니라
   가입 시점 약관을 따른다. 판이 특정되지 않으면 임의로 답하지 않는다.
2. **보장분석(계약 · 가입담보)과 약관(조항)을 결합한다** — 「약관에 있다」와
   「이 계약이 가입했다」를 구분하고, 걸리는 담보를 계약 전체에서 찾아 청구 누락을 막는다.
3. **약관북** — 답변한 약관이 고객별 폴더로 누적된다. 쓸수록 되묻기가 줄고,
   유료로 확보한 약관이 자산으로 남는다.

## 저장소 구성

```
src/orca/          로직 (외부 의존성 없음, 테스트로 검증)
  routing.py         질문 분류 → 소스 라우팅 (LLM은 분류만, 규칙은 코드)
  versioning.py      가입 시점 → 약관 판 특정
  clarify.py         턴 계획: 되묻기 / 검색 / 확보 요청 / 응답 처리
  coverage.py        보장분석(보유 계약 · 가입 담보) 연동
  links.py           약관북 — 고객 ↔ 약관 연결 장부
  catalog.py         상품 카탈로그 (등록/미등록 구분, 보험사 좁히기)
  requests.py        미등록 약관 확보 요청 · 승인 · 알림 대상
  pricing.py         등록 비용 (과금 단위 = 약관 파일 수)
  vendor_query.py    벤더 질의 — 개인정보 분리
  customers.py       FA별 담당 고객 (접근 통제)
  payout.py          지급 판정 (면책 우선) · 예상 수령액
  seed.py            초기 등록 목록 (실적 기반)
data/              상품 목록 시드 (손보 91 실적 + 생보 29 지정)
docs/              설계 문서 — product.md(제품 정의) · plan.md · market.md 부터 읽기
docs/mockups/      UX 목업 (insurance-ai.html — 진입 화면 + 흐름 3종)
tests/             277건
```

## 전제 (2026-08 기준)

- 약관 검색·생성은 VELUGA 벤더 API (모델 선택 가능, 등록 유료 · 파일 단위 과금 · 단가 미확정)
- 보장분석 업체는 리포트(계약 · 담보)만 제공, 약관은 제공하지 않음
- 초기 등록 200개 상품은 회사 부담, 그 외 약관은 요청 FA 부담 (동의 후 접수)
- 1차 오픈 대상은 FA, 2차(고객) 확장 시 재검토 항목은 docs/plan.md 0절
