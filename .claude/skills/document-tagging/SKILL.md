# 문서 태깅 (제목 중심)

## 이 작업의 성패 기준

태그를 정확히 붙이는 것보다 **적은 수의 태그를 여러 문서가 공유하게 만드는 것**이 목표다.
문서 하나하나에 딱 맞는 태그를 만들면 태그 수가 문서 수만큼 늘어나 검색에 아무 쓸모가 없어진다.
그래서 태그를 정할 때마다 이 질문을 통과시킨다.

> **"이 태그를 다른 문서에서도 다시 쓸 가능성이 있는가?"**

가능성이 낮으면 더 일반적인 상위 개념으로 바꾼다.

## 판단 순서

```
제목(파일명) 읽기 → 제외 대상인지 확인 → 핵심 주제 파악
  → 표준 태그 사전에서 태그 고르기 → (제목만으로 불명확할 때만) 본문 확인
```

제목만으로 의미가 명확하면 본문을 열지 않는다. 본문을 파고들수록 그 문서에만 맞는 세부 태그가 생겨나
태그 체계가 무너진다. 본문은 다음 경우에만 보조적으로 본다.

- 제목이 지나치게 짧거나 추상적일 때 (`자료_01`, `정리본`)
- 제목과 실제 내용이 다를 때
- 태그 두 개 중 어느 쪽인지 고르기 위한 최소 확인이 필요할 때

## 태깅 제외 대상

아래에 해당하면 태그를 만들지 않고 `태깅여부: 제외`로 표시한다.

| 유형 | 제목에서 알아보는 단서 |
| --- | --- |
| 보험사 약관 | `약관`, `특별약관`, `_Terms` |
| 상품안내장·상품설명서 | `상품설명서`, `상품안내장`, `가입설계서` |
| 상품요약서 | `상품요약서`, `요약서`, `_Summary` |
| 사업방법서·방법서 | `사업방법서`, `방법서`, `_사방` |
| 도서·스캔된 책 | `도서_` 분류, `오디오북`, 교재, 구분자 없는 단행본 제목 |

단, `(교육) 약관을 파고드는 자동차보험 상담 스킬업`처럼 약관을 **소재로 다룬 교육자료**는 약관 문서가
아니므로 제외하지 않는다. 제목에 제외 키워드가 있어도 문서의 정체가 다르면 정체를 우선한다.

## 태그 부여 규칙

1. **개수**: 최소 1개, 최대 3개. 3개를 억지로 채우지 않는다. 1개로 충분하면 1개만 붙인다.
2. **기존 태그 우선**: 새 태그를 만들기 전에 `references/tag-dictionary.md`에서 쓸 수 있는 태그를 먼저 찾는다.
   의미가 같거나 매우 비슷하면 무조건 기존 태그를 재사용한다. (`UW`·`인수심사`·`보험인수심사` → `#언더라이팅`)
3. **중간 수준의 구체성**: `#보험`, `#금융`, `#자료`, `#정보`, `#업무`, `#교육`처럼 너무 넓은 태그와
   `#당뇨병고객보험가입인수기준`처럼 너무 좁은 태그를 모두 피한다.
   넓은 태그는 보통 **대상이나 주제를 붙이면 살릴 수 있다**. `#교육` → `#설계사교육`,
   `#보험` → `#보험기초`처럼 "무엇에 대한 것인지"가 태그 이름에 드러나야 검색에 쓸모가 있다.
4. **복합 태그 금지**: 두 개념을 하나로 합치지 않고 쪼갠다.
   `#당뇨병인수기준` → `#당뇨병` + `#인수기준` / `#법인퇴직금절세` → `#법인` + `#퇴직금` + `#절세`.
   쪼개야 서로 다른 문서가 같은 태그를 공유할 수 있다.

**잘못된 예 → 올바른 예**

| 문서 제목 | ✗ | ✓ |
| --- | --- | --- |
| 당뇨병 고객 보험가입 인수기준 안내 | `#당뇨병보험가입인수기준` | `#당뇨병` `#언더라이팅` |
| 법인 CEO 퇴직금 절세전략 | `#법인CEO퇴직금절세전략` | `#법인` `#퇴직연금` `#절세` |

## 실행 방법

### 문서가 많을 때 (수십 건 이상) — 규칙 엔진 사용

문서 목록이 엑셀/CSV로 주어지면 손으로 하나씩 판단하지 않는다. 사람이 100건쯤 태깅하면
앞뒤 판단 기준이 흔들리는데, 규칙 파일에 기준을 적어두면 1만 건이든 같은 기준이 적용된다.

```bash
python3 scripts/tag_documents.py 문서목록.xlsx \
    -o 태깅결과.xlsx --json-out 태깅결과.json --text-out 문서별_태깅결과.txt
python3 scripts/review_tags.py 태깅결과.json -o 태그체계_최종검토리포트.md
```

`--text-out`은 아래 "출력 형식"의 문서별 블록을 그대로 텍스트로 뽑아준다. 엑셀 컬럼 형태가
필요하면 `-o` 결과를, 문서별 서술 형태가 필요하면 텍스트 파일을 쓴다.

- 제목 컬럼은 `파일명` → `게시물제목` → `제목` 순으로 자동 탐색한다. 필요하면 `--name-column`으로 지정.
- 결과 파일은 원본 컬럼을 모두 유지한 채 `태깅여부 / 태그1 / 태그2 / 태그3 / 판단근거`를 덧붙인다.

**돌린 뒤 반드시 검수한다.** 상위 태그 5~10개를 골라 실제로 붙은 문서를 20건씩 훑어보고,
엉뚱하게 붙은 태그가 있으면 규칙을 고친 뒤 다시 돌린다. 흔한 함정은 상품명에 들어간 단어다
(예: `무배당`의 `배당`을 배당주로 오인, `해약환급금 미지급형`의 `해약환급`을 계약관리 업무로 오인).

### 규칙을 고치는 방법

모든 판단 기준은 `scripts/tag_rules.json` 한 곳에 있다.

- `exclude`: 제외 대상 패턴. `except`에 넣은 패턴이 걸리면 제외하지 않는다.
- `book_heuristic`: 구분자 없는 단독 제목을 도서로 보되, `keep_patterns`에 걸리면 살린다.
- `tags`: `{tag, priority, patterns, not}`. `priority`가 낮을수록 먼저 선택되어 3개 안에 들어간다.
  `not`에 넣은 패턴이 제목에 있으면 그 태그는 붙지 않는다(오탐 차단용).
- `fallback`: 어떤 태그도 안 걸렸을 때 문서 분류 체계(폴더·부서 접두어)로 최소 1개를 보장한다.
- `umbrella_tags`: 세부 태그와 함께 붙는 것이 정상인 상위 태그(`#건강상식`, `#세금` 등).
  검토 리포트가 이 조합을 중복으로 오인하지 않도록 알려주는 역할을 한다.

**새 태그는 규칙 파일에 추가하는 방식으로만 늘린다.** 개별 문서를 보다가 즉흥적으로 태그를 만들면
그 태그는 그 문서에서만 쓰이고 끝난다. 규칙에 넣으려면 "이 패턴에 걸리는 문서가 앞으로도 여러 건
나오는가"를 먼저 확인하게 되므로, 재사용 가능한 태그만 남는다. 태그를 추가하면
`references/tag-dictionary.md`에도 정의를 적어 사전과 규칙을 같이 유지한다.

### 문서가 적을 때 (수 건~수십 건) — 직접 판단

규칙 엔진 없이 판단하되 기준은 동일하다. `references/tag-dictionary.md`의 태그 목록만 사용하고,
사전에 없는 개념이 필요하면 먼저 상위 개념으로 표현할 수 있는지 확인한다.

## 출력 형식

문서별 결과는 아래 형식을 따른다. 표(엑셀)로 낼 때는 같은 항목을 컬럼으로 만든다.

```
문서명: [파일명]

태깅여부: 대상 / 제외

태그1:
태그2:
태그3:

간단한 판단근거:
```

태그가 1~2개면 나머지는 빈칸으로 둔다.

## 최종 검토

전체 태깅이 끝나면 `scripts/review_tags.py`로 리포트를 만들고 다음을 확인한다.

1. 생성된 전체 태그 종류 수
2. 각 태그별 사용 문서 수
3. 1~3회만 사용된 태그 목록 — **지나치게 고유한 태그일 가능성이 높으므로 반드시 재검토**
4. 의미가 유사하거나 중복된 태그 목록 (동시 사용률이 높은 조합은 사실상 같은 말일 수 있다)
   — 단, `#건강상식` + `#당뇨병`처럼 상위 태그와 세부 태그가 짝을 이루는 조합은 의도된 구조이므로
   리포트에서 따로 분리해 보여준다. 이건 통합 대상이 아니다.
5. 통합을 권장하는 태그
6. 통합 후 최종 표준 태그 목록

리포트는 판단 재료일 뿐 결론이 아니다. 예를 들어 `#세금`과 `#상속`이 자주 함께 붙는다고 해서
반드시 합쳐야 하는 것은 아니다. 상속과 무관한 세금 문서가 따로 많다면 두 태그는 각자 역할이 있다.
통합 여부는 **"이 태그가 없으면 검색이 불편해지는가"**로 판단한다.
