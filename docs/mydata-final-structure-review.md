## 1. 판정 요약 — 위험도 재평가

전제가 확정되면서 **위험도가 상향된 항목**과 **해소된 항목**이 갈립니다.

| 쟁점 | 이전 판정 | 확정 후 | 사유 |
|---|---|---|---|
| 마이데이터 데이터 확보 | ⚠️ 허가 필요 | 🔴 **최대 쟁점** | 허가 미보유 + 재제공 구조 |
| 법인 분리에 의한 방어 | ✅ 유효 | 🔴 **방어력 상실** | 모자회사 = 동일 지배 |
| 툴 벤더 모델 (허가 부담 이전) | ✅ 돌파구 | ⚠️ **약화** | 모자회사 간 거래는 실질 판단 |
| 유전정보 격리 | 🔴 고위험 | ⚠️ **해소 가능** | 솔닥 보유 + 화살표 역전 시 |
| 의료기기(SaMD) | ⚠️ | ⚠️ 유지 | 식약처 확인 필요 |
| 보험모집 등록 | ⚠️ | ⚠️ 유지 | 인슈어런스AI가 등록 |

**총평:** 유전정보 문제는 해결 경로가 보이나, **① 교보 계약의 실질**과 **② 모자회사 구조**가
새로운 핵심 리스크로 올라왔습니다.

## 2. 🔴 최대 쟁점 — "월 사용료를 내고 구매"의 실질

이 프로젝트의 성패는 **여기 하나에 달려 있습니다.**

### 2.1 왜 문제인가

교보라이프플래닛은 마이데이터 사업자로서 **정보주체(고객)에게 서비스를 제공할 목적**으로
전 보험사 정보를 수집합니다. 이 정보를 **대가를 받고 다른 회사에 넘겨, 그 회사가 자기 사업에
사용하도록 하는 것**은 마이데이터 제도의 취지와 정면으로 충돌할 수 있습니다.

- 개인신용정보는 **거래 대상 물건이 아닙니다.**
- "월 사용료"라는 표현이 **데이터 판매**로 해석되면 리스크가 매우 큽니다.
- 마이데이터 사업자의 수집정보 제3자 제공은 **엄격히 제한**됩니다.

### 2.2 세 가지 가능한 실질 — 판정이 완전히 다릅니다

| 구조 | 데이터 위치 | 서비스 주체 | 판정 |
|---|---|---|---|
| **(A) 업무위탁** — iFA AI가 교보의 수탁자 | 교보 환경 | **교보** | ✅ 가능성 높음 |
| **(B) 화이트라벨** — 교보 서비스에 iFA 툴 탑재 | 교보 환경 | **교보** | ✅ 가능 |
| **(C) 데이터 제공** — iFA AI 서버로 수신해 자체 서비스 | **iFA AI** | iFA AI | 🔴 **위법 소지 큼** |

### 2.3 지금 당장 확인해야 할 단 하나의 질문

> **개인신용정보 원본이 iFA AI 서버로 넘어옵니까, 아니면 교보 환경 안에서 처리됩니까?**

- **넘어온다** → 구조 (C). 계약서 문구와 무관하게 재검토가 필요합니다.
- **교보 안에서 처리된다** → 구조 (A)/(B). **적법하게 설계 가능합니다.**

### 2.4 (A)/(B)로 갈 때의 사업적 함의
- 최종 서비스 주체가 **교보**가 됩니다. iFA AI는 솔루션 공급자로 남습니다.
- 고객 접점과 브랜드를 교보가 가져갑니다.
- 대신 **허가·컴플라이언스 부담을 교보가 집니다.** iFA AI는 허가 불필요.
- **월 사용료의 성격도 "데이터 대가"가 아니라 "시스템·API 이용료"로 정리되어야 합니다.**

### 2.5 추가 검토 필요 — 보험사가 전 보험사 정보를 보는 구조
교보는 **보험사이면서 마이데이터 사업자**입니다. 전 보험사 가입내역을 보고 보험을 추천하는 구조는
**자사 상품 유인** 문제가 제기될 수 있습니다. 추천 알고리즘의 중립성 입증 체계가 필요합니다.

## 3. 🔴 모자회사 구조 — 분리 방어가 성립하지 않습니다

### 3.1 확정 내용
- **모회사: iFA AI / 자회사: 인슈어런스AI**

### 3.2 문제
앞선 검토에서 "법인을 나누면 유전정보 문제를 완화할 수 있다"고 했으나,
**모자회사는 동일 지배관계**이므로 규제기관은 통상 **한 몸으로 봅니다.**

특히 다음 구조는 우회로 판단될 위험이 높습니다.

```
iFA AI (모회사) ── 유전 포함 다축 분석
      │
      ▼ 툴 제공
인슈어런스AI (자회사) ── 보험 설계·추천
```

→ 형식은 두 법인이지만, 실질은 **"유전정보를 아는 그룹이 보험을 판다"**로 읽힙니다.

### 3.3 그럼에도 성립시키는 방법

모자회사여도 다음을 모두 갖추면 방어력이 생깁니다.

- [ ] **유전정보가 iFA AI로 애초에 들어오지 않음** ← 가장 중요
- [ ] 보험 추천 모델의 **피처 목록에 유전 변수 0개** 문서화
- [ ] 양사 간 데이터 이동에 **위탁·제공 계약서** 존재 및 실질 부합
- [ ] 인력 겸직 최소화, 시스템·계정 분리
- [ ] 유전 관련 조회 이력 **전량 감사로그** 보존

**핵심은 3.3의 첫 항목입니다.** 유전정보를 안 받으면 나머지 논쟁이 대부분 사라집니다.

## 4. ✅ 유전정보 — 해결 경로 확정

솔닥이 보유한다는 점이 확인되어, **화살표 역전 구조**로 해소 가능합니다.

```
[수정 구조]
  iFA AI ──검진·투약──▶ 솔닥 (유전 보유·미반출) ──▶ 건강리포트 ──▶ 고객
     │
     └──▶ 인슈어런스AI 보험 라인 (유전정보 수신 이력 0건)
```

### 조건
- 솔닥이 **유전자검사기관 / DTC 인증기관** 자격 보유 확인
- 유전정보는 **솔닥 밖으로 반출하지 않음** (원본·파생 모두)
- iFA AI → 솔닥 검진·투약 전달 시 **민감정보 제3자 제공 동의** 취득
- 리포트는 솔닥 명의 또는 공동 명의로 고객에게 직접 전달

### 포기해야 하는 것
- **"우리만 4축을 동시에 봅니다"** — 4축을 동시에 보는 주체가 없어집니다.

## 5. ⚠️ 유지되는 기존 쟁점

| 쟁점 | 조치 |
|---|---|
| **동의 유효기간** | "1회 인증 후 영구"는 불가. 연 1회 갱신 + 목적별 개별 동의 |
| **의료기기(SaMD)** | 식약처 확인 요청. "AI 질병예측" 표현 정비 |
| **보험모집 등록** | 인슈어런스AI가 보험대리점 등록 |
| **변액펀드 추천** | 투자자문업 해당 여부 검토 |
| **약관 매핑 DB** | 전 보험사 담보코드 정규화 — **실제 개발 공수의 대부분** |
| **전송 과금** | 고객수 × 보험사수 비례 변동비 |

## 6. 권고 구조

```
      [고객]
         │ 전송요구 (유효기간 1년, 갱신)
         ▼
  ┌──────────────────────────┐
  │  교보라이프플래닛         │  ← 마이데이터 허가 보유 주체
  │  전 보험사 정보 수집·보관 │  ← 데이터는 여기 머무름
  │   └ iFA AI 분석엔진 탑재  │  ← 위탁/화이트라벨
  └──────────┬───────────────┘
             │ 분석 결과만
             ▼
      인슈어런스AI ── 보장분석·설계 (보험대리점 등록)
             │
             │ 검진·투약 (별도 동의)
             ▼
         솔닥 ── 유전 보유·미반출 ── 건강리포트 ──▶ 고객
```

**원칙 세 가지**
1. **데이터는 허가 보유자(교보)에 머문다** — iFA AI는 엔진을 제공한다
2. **유전정보는 솔닥을 벗어나지 않는다**
3. **모집 행위는 등록 주체(인슈어런스AI)가 한다**

## 7. 우선순위 액션

### 🔴 P0 — 다른 모든 일보다 먼저
1. **교보 계약서 실질 확인** — 원본 데이터가 iFA AI 서버로 오는가?
   → 온다면 구조 (A)/(B)로 **계약 재설계**
2. **"월 사용료"의 성격 명확화** — 데이터 대가가 아닌 시스템 이용료로 정리
3. **모자회사 구조 관련 법무 의견서** — 유전 격리 전제 하 방어 가능성

### 🟠 P1
4. 유전 화살표 역전 구조 확정 및 솔닥 자격 확인

6. 인슈어런스AI 보험대리점 등록
7. 동의 설계 전면 재작성 (유효기간 + 목적별 분리)

### 🟡 P2
8. 약관 매핑 DB 구축 계획 (최대 공수)

10. 감사로그·피처 목록 증빙 체계

## 8. 결론

**해결 불가능한 항목은 없습니다. 다만 현재 조합이 방어력 측면에서 가장 취약합니다.**

- 허가는 **빌려 쓰고** (직접 보유 아님)
- 법인 분리는 **모자회사** (형식적 분리 위험)
- 여기에 **유전정보**까지 얹혀 있었습니다

셋 중 **유전정보는 솔닥 격리로 해소 경로가 확정**되었습니다.
남은 두 가지는 **교보 계약의 실질**이 결정합니다.

> **원본 데이터가 iFA AI로 넘어오지 않는다면 — 이 사업은 적법하게 설계 가능합니다.**
> **넘어온다면 — 계약 구조부터 다시 짜야 합니다.**

이것이 현재 시점의 단일 최대 확인 사항입니다.
