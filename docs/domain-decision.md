## 1. 결정 요약

보유 중인 3개 도메인 가운데 **`insuranceai.co.kr`을 정본(canonical)으로 확정**하고,
나머지 2개는 정본으로 301 영구 리다이렉트하여 유입을 회수한다.

| 도메인 | 역할 | 처리 |
|---|---|---|
| **`insuranceai.co.kr`** | **정본** — 웹 서비스 및 이메일 전부 | 실서비스 연결. `www` → 루트로 통일 |
| `insuranceai.kr` | 별칭 — SMS·QR·오프라인 단축 링크 | 301 → `https://insuranceai.co.kr` |
| `insurance-ai.co.kr` | 방어용 (오타·구전 오류 회수) | 301 → `https://insuranceai.co.kr` |

브랜드 코어 문자열은 **하이픈 없는 `insuranceai`로 고정**한다.
향후 `insuranceai.com` / `insuranceai.ai` 인수 시 문자열이 그대로 승계되어,
브랜드 자산이 끊기지 않도록 하기 위함이다.

## 3. 판단 근거

### 3.1 발화·구전 — 하이픈 탈락의 결정적 사유

보험은 전화 상담·설계사 대면 비중이 큰 업종이다. 상담 현장에서 도메인은 **눈이 아니라 입으로** 전달된다.

> "인슈어런스 **하이픈** 에이아이 점 씨오 점 케이알"

하이픈은 발화 길이를 늘리고, 상당수 통화에서 "하이픈이 뭐예요?"라는 되물음을 유발한다.
구전 단계에서 이탈을 만드는 부품이므로 정본에서 제외한다.

### 3.2 신뢰·규제 신호 — `.co.kr` 우위

보험은 개인정보·계약·금융을 다루는, **피싱 사칭의 상위 표적 업종**이다.
국내 소비자에게 학습된 금융사 도메인 패턴은 `.co.kr` 또는 `.com`이며,
`.kr` 단독은 여전히 캠페인 페이지·단축 링크의 인상이 남아 있다.
문자 메시지로 링크를 수신했을 때 스미싱 의심을 유발할 여지가 `.co.kr` 대비 크다.

### 3.3 검색·마케팅 — SEO는 변수 아님

- 구글은 EMD(정확일치 도메인) 가중치를 오래전 제거했고, 하이픈 유무로 순위가 갈리지 않는다.
- 네이버는 도메인 문자열보다 브랜드 검색량·콘텐츠 생태계로 판단한다.
- **결론: SEO 축에서는 세 후보 간 실질 차이가 없다.**

다만 실효 변수가 하나 있다 — **SMS/QR 길이**.
`insuranceai.kr`(15자)은 `insuranceai.co.kr`(18자)보다 3자 짧고 QR 밀도가 낮다.
이 이점은 정본을 바꾸지 않고 **별칭으로 유지**하는 것으로 취한다.

### 3.4 자산·확장 — 코어 문자열 고정

정본 선택보다 오래 가는 결정은 **코어 문자열을 무엇으로 고정하느냐**이다.
`insuranceai`로 고정하면 훗날 `.com` / `.ai` 인수 시 브랜드가 그대로 승계된다.
반대로 `insurance-ai`를 정본으로 운영하다 `insuranceai.com`으로 이전하면,
그때까지 축적된 백링크·명함·인쇄물·구전이 한 번 끊긴다.

### 3.5 운영 리스크

- 3개 도메인을 모두 보유 중이므로, 301 묶음으로 오타·구전 오류 유입을 전량 회수할 수 있다.
- 이메일 도메인은 정본과 일치시킨다(`@insuranceai.co.kr`). 신규 도메인이므로 발송 인증 설정이 필수다.
- 실측상 정본 후보가 이미 CDN에 연결되어 있어 기술 전환 비용이 가장 낮다.

## 4. 라이브 실행 체크리스트

### DNS / 웹
- [ ] `insuranceai.co.kr` — 서비스 오리진 연결, `www.insuranceai.co.kr` → 루트 301
- [ ] `insuranceai.kr` — 전체 경로 보존 301 → `https://insuranceai.co.kr`
- [ ] `insurance-ai.co.kr` — 전체 경로 보존 301 → `https://insuranceai.co.kr`
- [ ] 3개 도메인 전부 HTTPS 인증서 발급 (리다이렉트 전용 도메인도 인증서 필요 — 없으면 브라우저 경고 후 리다이렉트되어 신뢰도 손상)
- [ ] HTTP → HTTPS 강제 리다이렉트, HSTS 적용

### 검색 / 중복 콘텐츠 방지
- [ ] 모든 페이지에 `<link rel="canonical" href="https://insuranceai.co.kr/...">`
- [ ] `sitemap.xml` / `robots.txt`는 정본 도메인 기준으로만 작성
- [ ] Google Search Console · 네이버 서치어드바이저에 **정본만** 등록
- [ ] OG 태그(`og:url`, `og:image`)를 정본 기준으로 — 카카오톡/문자 링크 미리보기 대응

### 이메일 (라이브 전 필수)
- [ ] `@insuranceai.co.kr` 메일 서비스 연결 (MX)
- [ ] **SPF** 레코드 등록
- [ ] **DKIM** 서명 활성화
- [ ] **DMARC** 정책 등록 (`p=none`으로 시작 → 리포트 확인 후 `quarantine` 상향)
- [ ] 별칭 2개 도메인에 SPF `-all` 널 레코드 등록 (사칭 발송 차단)

> 신규 도메인은 발송 평판이 없다. 위 3종 인증 없이 첫 대량 발송을 하면 통째로 스팸함으로 분류될 위험이 크다.

### 브랜드 표기 통일
- [ ] 명함·브로슈어·계약서·앱스토어 소개·SNS 프로필 전부 `insuranceai.co.kr`로 통일
- [ ] 오프라인 QR·SMS 발송에 한해 `insuranceai.kr` 사용 허용 (그 외 채널에서는 정본만 노출)

## 5. 재검토 트리거

아래 상황이 발생하면 본 결정을 재검토한다.

1. **`insuranceai.com` 인수 성사** → 정본을 `.com`으로 이전, `insuranceai.co.kr`은 301 별칭으로 강등
2. **유입 채널 구조 변화** — 웹 검색 유입이 미미하고 카카오/SMS/QR이 압도적이 될 경우, `insuranceai.kr` 정본 승격 재검토
3. **해외 진출 착수** — 국가코드 TLD(`.co.kr`)가 글로벌 신뢰도에 제약이 되는 시점

## 6. 미결 사항

- `.com` 2종 인수 검토 — 보유자 확인, 브로커 경유 협상 타진, 예산 범위 결정 (별도 안건)
