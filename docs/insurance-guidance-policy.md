# 보험 안내 정책 — 최신성 / 보험료 조문 초안

기존 정책 문서의 **1-3(신설), 2-6(보강), 3-1(개선안)** 에 병합할 초안이다.
대상은 상품 안내 AI의 응답 생성 및 출력 단계 전반이다.

---

## 1-3. 보험료 안내 최신성 원칙 (신설, 7~12항)

### 7항 — 최신의 정의

"최신"은 개정코드 숫자가 가장 큰 자료가 아니라, **기준시점(asOf)에 실제로 판매 중인 판**을 말한다.

| 상황 | asOf |
|---|---|
| 일반 안내 | 안내 당일 |
| 과거 가입 상품 | 가입일 |
| 갱신형 상품 | 직전 갱신일 |
| 시행 예정 개정 문의 | 별도 취급, "○년 ○월 시행 예정" 라벨 필수 |

### 8항 — 최신 판별 우선순위

1. **현재 판매 상품 데이터의 개정코드와 일치하는 자료**
2. 목록 미등재 상품에 한해 **개정코드(YYMM) 최신값**
3. 개정코드가 동일한 자료가 복수일 때 **게시일 최신본 1건**

목록 기준일 이후 발행된 상품소식지에 해당 상품의 개정·판매중지 공지가 있으면 1을 신뢰하지 않고 10항의 보류로 전환한다.

게시일(업로드일)을 1·2순위로 사용하지 않는다. 과거 자료의 일괄 업로드·재업로드로 구버전이 최신으로 뒤집히기 때문이다.

| 검색된 파일의 개정코드 | 판정 |
|---|---|
| 목록과 일치 | 채택 |
| 목록보다 큼 | 미시행·예정본 의심 → 소식지 확인 → 시행 공지가 있으면 보류, 없으면 제외 |
| 목록보다 작음 | 과거판, 제외 (12항 예외만 허용) |
| 개정코드 없음 | 보류 |
| 상품이 목록 미등재 | '현재 판매 중' 안내 금지 (2-2) |

### 9항 — 혼재된 정보의 처리

혼재된 정보는 **개정코드 최신본 기준**으로 답변한다. 개정코드가 없을 때만 게시일을 사용한다. 과거 버전의 수치는 인용·비교에서 제외한다.

혼재는 두 유형으로 나누어 처리하며, 하나의 규칙으로 뭉뚱그리지 않는다.

| 유형 | 예 | 처리 |
|---|---|---|
| **해소 가능** — 개정 전후 값의 시점 차이 | 2506판 거치 25년 / 2509판 거치 20년 | 최신본만 안내. **상충 사실을 표시하지 않는다** |
| **해소 불가** — 동일 개정판 내 모순 | 같은 자료 내 10,641원 / 10,610원 | **보류** → 10항 |

해소 가능한 혼재를 사용자에게 "재확인이 필요합니다"로 넘기지 않는다.

**최신값 안내 시 근거 시점 표기.** 상충을 표시하지 않는 것과 근거를 밝히는 것은 다르다. 최신값을 안내할 때는 어느 판을 근거로 했는지 **개정코드와 함께** 표기한다.

- 금지: "2506 자료에는 25년, 2509 개정판에는 20년으로 나와 있어 재확인이 필요합니다"
- 권장: "**최신 개정판(2509) 기준** 최소 거치기간은 20년입니다"

이 표기는 사용자가 구버전 자료를 보유한 경우 차이를 인지하게 하고, 답변의 근거 시점을 기록에 남긴다.

단, **판별에 성공한 경우에만** 붙인다. 최신 여부를 확인하지 못한 상태에서 "최신 기준"을 관용구로 덧붙이면 근거 없는 보증이 되므로, 이 경우는 10항의 보류로 간다. 개정코드 없이 "최신 기준"만 표기하는 것도 사후 검증이 불가능하므로 허용하지 않는다.

### 10항 — 보류 및 고정 응답 전환

다음 중 하나에 해당하면 답변 생성을 중단하고 고정 응답으로 전환한다.

- 최신 파일이 확인되지 않음
- 동일 개정판 내 수치 모순 (9항 해소 불가)
- 최신 후보의 개정코드가 현재 판매 상품 데이터와 불일치
- 개정코드·적용일 모두 결측
- 개정코드가 asOf보다 2개월 초과 미래로 표기 (오탈자 의심)
- **세트 불일치** — 동일 답변 내 인용 자료의 개정코드가 서로 다름

상충 감지 결과에 경고 문구를 덧붙여 답변을 계속하는 경로를 제거한다. 감지 시 분기는 보류 하나뿐이다.
시스템 내부 경고문(영문 포함)은 사용자 대면 출력에 노출하지 않고 고정 응답으로 치환한다.

### 11항 — 자격요건 조합 추론 금지

가입연령, 연금개시연령, 거치기간, 납입기간 등 **자격요건은 자료에 명시된 문장만 인용**한다. 자료 조각을 조합하거나 계산하여 특정 고객의 충족 여부를 판단하지 않는다.

- 금지: `가입연령 15~50세` + `개시연령 50세부터` → "45세 고객은 60세부터 수령 가능"
- 명시되지 않은 경우 "확인 필요"로 처리한다.

최신 자료를 사용하더라도 조합 추론이 남아 있으면 결과는 동일하게 틀린다.

### 12항 — 예외

과거 가입 상품에 대한 안내는 가입시점의 약관·상품자료를 기준으로 한다. 갱신형은 직전 갱신시점 자료를 기준으로 한다.

## 2-6. 자료 선택 우선순위 (보강)

| 순위 | 자료 | 역할 |
|---|---|---|
| 1 | 현재 판매 상품 데이터 | 판매 여부 및 정본 개정코드 판정 |
| 2 | 최신 파일 (개정코드 기준) | 내용 근거 |
| 3 | 기타 공식자료 | 보조 |
| 참조 | 상품소식지 | 판별 기준이 아니라 **목록 신선도 검증기**. 목록 기준일 이후 변경 공지 확인용 |

예외: 과거 가입 건은 가입시점 자료 (1-3 12항).

## 3-1. 보험료 안내 답변 최적화

### 금지 / 허용 구분

| 구분 | 내용 |
|---|---|
| **금지** | 개인 산출 보험료 금액, 조건 없는 추정치, 타사 비교 수치, 사용자가 제시하지 않은 조건을 임의 가정한 뒤의 금액 제시 |
| **허용** | 납입 방법, 갱신 주기 등 제도적 설명 (최신 파일 근거) |
| **허용** | 최저 기본보험료 등 **상품 가입요건**으로서의 금액 (예: 월 20만원 이상, 5년납 30만원 이상) |
| **허용** | 가입금액·보험금 (예: 암진단금 1,000만원) |
| **별도 관리** | 공시이율·최저보증이율·유지보너스율 등 변동 수치. 매월 변경되므로 보험료보다 최신성 요구가 높다. 최신본 확인 불가 시 안내하지 않는다 |

### 출력단 하드필터

프롬프트 지시만으로는 차단되지 않으므로 응답 렌더링 직전에 패턴 차단을 둔다.

- 차단 대상: `월 보험료`, `납입보험료`, `보험료 약` 문맥의 금액
- 비차단: 가입금액·보험금·최저 기본보험료

가입금액까지 함께 차단하면 담보 설명이 불가능해져 필터가 무력화되므로 문맥 구분이 필수다.

### 상품 추천 요청의 응답 형식

특정 상품을 나열하고 금액을 제시하는 형식은 비교권유로 읽힐 수 있다. `추천해줘` 유형의 요청은 상품 나열이 아니라 **선택 기준 설명 + 상담 연결**로 응답한다. 사용자가 조건을 제시하지 않은 경우 조건을 되묻거나 상담으로 연결하고, 조건을 임의 가정하지 않는다.

### 고정 응답 문구

**(1) 보험료 금액 요청**

> 보험료는 나이·성별·가입담보·납입기간에 따라 달라지고 개정에 따라 수시로 변경되어, 정확한 금액은 안내드리기 어렵습니다.
> 담보 구성이나 갱신 주기 등 상품 구조는 안내드릴 수 있으며, 정확한 보험료는 [상담 링크]에서 확인하실 수 있습니다.

**(2) 최신 파일 미확인 / 동일 개정판 내 모순**

> 해당 내용은 최신 자료 확인이 필요하여 안내를 보류합니다.
> 정확한 내용은 [상담 링크]에서 확인하실 수 있습니다.

**(3) 자격요건 미명시**

> 문의하신 조건의 충족 여부는 상품 자료에 명시되어 있지 않아 확인이 필요합니다.
> [상담 링크]에서 확인하실 수 있습니다.

## 부록 A. 파일–상품 매칭 규칙

판매목록의 상품명과 실제 파일명이 일치하지 않는 경우의 식별 순서.

1. **문서 표지(첫 페이지)의 정식 상품명 + 개정코드** — 파일명은 임의로 작성되므로 신뢰하지 않는다
2. **별칭 테이블** (`data/product_aliases.csv`)
3. **정규화된 파일명** — `무배당`, `(무)`, 개정코드, 종·플랜·채널, 문서종류(약관/요약서/설명서), 공백·특수문자 제거 후 비교. 부록의 기본상품명 컬럼을 키로 사용
4. 실패 시 보류

부분일치·유사도만으로 자동 채택하지 않는다 (`어린이CI보험` ↔ `어린이보험`은 다른 상품이다).

미매칭 건은 로그로 적재하여 월 1회 별칭 테이블을 보강한다.

### 매칭 실패와 미등재의 구분

| 상황 | 응답 |
|---|---|
| 목록에 있음 + 파일 매칭 실패 | "판매 중이나 자료 확인 불가" → 보류 |
| 목록에 아예 없음 | '현재 판매 중' 안내 금지 |

이 둘을 섞으면 판매 중인 상품을 판매종료로 안내하게 된다.

## 부록 B. 데이터 스키마

### `data/current_sales_products.csv`

목록 상단 또는 별도 필드에 **기준일(스냅샷 일자)** 을 반드시 유지한다. 기준일이 없으면 상품소식지와의 대조가 불가능하다.

`적용일`·`판매종료일`은 확보 전까지 공란으로 두되, 확보 시 1-3 8항의 유효성 필터에 사용한다.

### `data/product_aliases.csv`

상품 1건당 알려진 표기 변형을 등록한다. 40건 규모에서는 수작업으로 구성하고 미매칭 로그로 증분 보강한다.
