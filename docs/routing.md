# 어느 질문에서 약관을 쓰는가

`src/orca/routing.py` · `src/orca/types.py`의 설계 근거.

## 구조

질문 분류(의도 파악)는 LLM이 하고, **어느 소스를 쓸지와 시점 특정이 필요한지는 코드가 정한다.**
보상 판단이 걸린 영역이라 라우팅 규칙까지 매번 LLM 생성에 맡기지 않는다.
이렇게 나누면 규칙이 표 하나(`ROUTING_TABLE`)에 모이고, 테스트로 검증된다.

```
질문 → [LLM 분류] → QuestionType → [ROUTING_TABLE] → 소스 + 시점 민감도
```

## 질문 유형과 처리

| 유형 | 예시 | 소스 | 시점 특정 |
| --- | --- | --- | --- |
| `concept` | 「글라이드패스가 뭔가요?」 | Micky | 불필요 |
| `sales` | 「변액연금 잘 팔려면?」 | Micky | 불필요 |
| `product_info` | 「오토파일럿 변액연금 어떤 상품이야?」 | VELUGA | 권장 |
| `benefit_term` | 「골절진단비가 뭔가요?」 | VELUGA | 불필요 |
| `coverage` | 「음주운전 사고인데 보험금 나오나요?」 | VELUGA | **필수** |
| `underwriting` | 「고혈압 있어도 가입되나요?」 | VELUGA | **필수** |
| `procedure` | 「진단금 청구할 때 뭐가 필요해요?」 | VELUGA | 권장 |
| `contract_value` | 「이 고객 진단금 얼마 나와요?」 | — | 범위 밖 |

**시점 특정 민감도**

- **필수** — 판이 다르면 답이 달라진다. 특정 없이 답하지 않는다.
- **권장** — 특정하면 정확하지만, 없으면 일반론임을 밝히고 답한다.
- **불필요** — 약관 판과 무관하다.

## 판단 기준 세 가지

**1. 「상품마다 달라지는가」가 약관 사용 여부를 가르고,
「판마다 달라지는가」가 특정 필요 여부를 가른다.**
보험 이론 · 제도 일반은 상품과 무관하므로 Micky로 충분하다.
보장 범위 · 면책 · 인수 조건은 상품과 판마다 다르므로 약관 + 특정이 필요하다.

그 사이에 **담보 용어 설명**(`benefit_term`)이 있다.
「골절진단비가 뭔가요?」의 정의는 약관에 있지만 약관 공통이라,
**약관을 검색하되 상품 · 판은 특정하지 않고** 일반 설명으로 답한다.
상품이 언급되어 하나로 떨어지면 검색 범위만 조용히 좁히고, 모호해도 되묻지 않는다.
금액 · 지급 조건은 상품마다 다르므로 그 점만 답변에서 밝힌다.

| | 약관 사용 | 특정 |
| --- | --- | --- |
| 글라이드패스가 뭔가요? (`concept`) | ✗ | ✗ |
| 골절진단비가 뭔가요? (`benefit_term`) | ✓ | ✗ |
| 골절돼서 입원했는데 나오나요? (`coverage`) | ✓ | ✓ |

**2. 상품이 특정되면 개념 · 세일즈 질문도 약관을 함께 쓴다.**
「오토파일럿 변액연금 잘 팔려면?」은 세일즈 화법(Micky)과 상품 내용(VELUGA)이 함께 필요하다.
`route()`가 이 경우 VELUGA를 덧붙인다.

**3. 금액을 묻는 질문은 약관으로 답할 수 없다.**
약관은 **「지급사유에 해당하는가」까지만** 답한다.
실제 지급액은 가입금액에 달렸고 그건 계약 정보(Cloud DATA, 이번 범위 밖)다.
이 경계를 흐리면 AI가 임의로 금액을 말하게 되므로 `contract_value`로 분리해 차단한다.

## 약관의 담보와 계약의 담보는 다르다

하나의 약관에는 그 상품에서 **가입할 수 있는 담보가 전부** 들어 있다.
골절진단비 · 수술비 · 입원일당 · 후유장해 … 실제 계약은 그중 일부만 가입한다.

따라서 약관에서 골절진단비 조항을 찾았다고 「지급됩니다」라고 답하면,
그 특약에 가입하지 않은 계약에는 **틀린 답**이 된다.
계약별 가입 담보는 계약 정보(Cloud DATA)이며 이번 범위 밖이다.

**약관 기반 지급 답변은 언제나 조건부다** (`TurnPlan.needs_enrollment_caveat`).

> 약관상 담보 기준입니다. 실제 지급은 해당 담보에 가입한 계약에 한하므로,
> 가입 담보를 함께 확인해 주세요.

### 담보를 지목했는지가 답변 범위를 가른다

| 질문 | 범위 | 답변 |
| --- | --- | --- |
| 「골절진단비 나오나요?」 | `SPECIFIC` | 그 담보의 지급사유 · 면책을 깊게 |
| 「골절됐는데 뭐 받을 수 있어요?」 | `ENUMERATE` | 걸릴 수 있는 담보를 **모두** 제시 |

담보를 지목하지 않은 질문에 하나만 답하면 FA가 청구 가능한 담보를 놓친다.
골절 사고 하나에도 골절진단비 · 상해입원일당 · 수술비 · 후유장해가 동시에 걸린다.
분류기가 `benefit_mentioned`를 뽑고, `BenefitScope`가 이 구분을 담는다.

## 분류가 애매한 경우

프롬프트에 판단 기준을 명시해 두었다.

- 「이런 경우에 되나요 / 나오나요 / 해당되나요」 → `coverage`
- 「얼마인가요」처럼 금액 자체를 묻는다 → `contract_value`
- 상품을 특정하지 않은 일반 용어 설명 → `concept`

## 검증

분류기 프롬프트는 실제 FA 질문 로그로 검증해야 한다.
현재는 유형별 예시로만 규칙을 고정해 둔 상태이며,
질문 로그를 받으면 오분류가 잦은 경계(특히 `coverage` ↔ `product_info`,
`procedure` ↔ 사내 절차)를 프롬프트에 반영한다.
