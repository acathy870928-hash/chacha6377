# 어느 질문에서 약관을 쓰는가

`src/orca/routing.py` · `src/orca/types.py`의 설계 근거.

## 구조

질문 분류(의도 파악)는 LLM이 하고, **어느 소스를 쓸지와 시점 특정이 필요한지는 코드가 정한다.**
보상 판단이 걸린 영역이라 라우팅 규칙까지 매번 LLM 생성에 맡기지 않는다.
이렇게 나누면 규칙이 표 하나(`ROUTING_TABLE`)에 모이고, 테스트로 검증된다.

```
질문 → [LLM 분류] → QuestionType → [ROUTING_TABLE] → 소스 + 시점 민감도
```

## 질문 유형과 처리

| 유형 | 예시 | 소스 | 시점 특정 |
| --- | --- | --- | --- |
| `concept` | 「글라이드패스가 뭔가요?」 | Micky | 불필요 |
| `sales` | 「변액연금 잘 팔려면?」 | Micky | 불필요 |
| `product_info` | 「오토파일럿 변액연금 어떤 상품이야?」 | VELUGA | 권장 |
| `coverage` | 「음주운전 사고인데 보험금 나오나요?」 | VELUGA | **필수** |
| `underwriting` | 「고혈압 있어도 가입되나요?」 | VELUGA | **필수** |
| `procedure` | 「진단금 청구할 때 뭐가 필요해요?」 | VELUGA | 권장 |
| `contract_value` | 「이 고객 진단금 얼마 나와요?」 | — | 범위 밖 |

**시점 특정 민감도**

- **필수** — 판이 다르면 답이 달라진다. 특정 없이 답하지 않는다.
- **권장** — 특정하면 정확하지만, 없으면 일반론임을 밝히고 답한다.
- **불필요** — 약관 판과 무관하다.

## 판단 기준 세 가지

**1. 「상품마다 달라지는가」가 약관 사용 여부를 가른다.**
용어 정의나 제도 일반은 상품과 무관하므로 Micky로 충분하다.
반면 보장 범위 · 면책 · 인수 조건은 상품과 판마다 다르므로 약관이 필요하다.

**2. 상품이 특정되면 개념 · 세일즈 질문도 약관을 함께 쓴다.**
「오토파일럿 변액연금 잘 팔려면?」은 세일즈 화법(Micky)과 상품 내용(VELUGA)이 함께 필요하다.
`route()`가 이 경우 VELUGA를 덧붙인다.

**3. 금액을 묻는 질문은 약관으로 답할 수 없다.**
약관은 **「지급사유에 해당하는가」까지만** 답한다.
실제 지급액은 가입금액에 달렸고 그건 계약 정보(Cloud DATA, 이번 범위 밖)다.
이 경계를 흐리면 AI가 임의로 금액을 말하게 되므로 `contract_value`로 분리해 차단한다.

## 분류가 애매한 경우

프롬프트에 판단 기준을 명시해 두었다.

- 「이런 경우에 되나요 / 나오나요 / 해당되나요」 → `coverage`
- 「얼마인가요」처럼 금액 자체를 묻는다 → `contract_value`
- 상품을 특정하지 않은 일반 용어 설명 → `concept`

## 검증

분류기 프롬프트는 실제 FA 질문 로그로 검증해야 한다.
현재는 유형별 예시로만 규칙을 고정해 둔 상태이며,
질문 로그를 받으면 오분류가 잦은 경계(특히 `coverage` ↔ `product_info`,
`procedure` ↔ 사내 절차)를 프롬프트에 반영한다.
