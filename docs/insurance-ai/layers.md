# insurance AI — 레이어 구성 (Layer Architecture)

> 고객의 질문 하나가 어떤 층을 지나 답이 되는지를 기준으로 구성한 계층 구조입니다.
> 회사 전체 아키텍처는 [architecture.md](../architecture.md).

---

## 1. 전체 구성 — 6개 레이어

```
 L6  사용자 (Client)
      B2C 고객 (앱/웹) │ B2B 보험사·GA (API·White Label)
──────────────────────────────────────────────────────────────
 L5  서비스 (Service) — insurance AI 앱/웹
      인증·로그인 │ 대화 UI │ 전문 서비스 연결 │ B2B: API Gateway·테넌트 격리
──────────────────────────────────────────────────────────────
 L4  에이전틱 (Agentic) — 마스터 오케스트레이터
      의도 분류(Rule→LLM 2-Tier) │ 페르소나 인계 판단 │ 컨텍스트 관리
      대화 ↔ 워크플로우 모드 전환
──────────────────────────────────────────────────────────────
 L3  페르소나 & 에이전트
      페르소나: insurance AI │ MediCode │ VFA │ HopePlan │ Legacy Plan
      에이전트: 상품(약관)★ │ 계약 │ 청구 │ 연금  — 단계적 확장
      가드레일 내장 Tool Calling: 호출 전 검증 레이어 필수 통과
──────────────────────────────────────────────────────────────
 L2  코어 지능 (Core Intelligence) — Insurance Vertical AI™
      보험지식 │ 보험법령 │ 보험상품 │ 보험약관 │ 보험실무 │ 의사결정 엔진
      + 정본 계층: Manifesto · Charter · 운영 지침 = 시스템 프롬프트
──────────────────────────────────────────────────────────────
 L1  데이터 (Data)
      보험산업 전문지식 │ 보험약관 │ 고객 계약 │ 마이데이터 │ 법령·공공·제휴
```

★ = 벨루가 6개월 구축의 핵심 범위

## 2. 레이어별 정의

### L1 — 데이터 레이어

insurance AI가 근거로 삼는 원천. **연결 여부가 곧 답변 범위**입니다 ([지침 5-4](guidelines.md)).

| 데이터 | 내용 | 쓰임 | 상태 |
| --- | --- | --- | --- |
| 보험산업 전문지식 | 보험이론·재무·금융법령·기관 자료 | 보험 일반 질문의 지식 기반 | ✅ |
| 법령·공공·제휴 | External MCP | 법령 근거, 공공정보 | ✅ |
| **보험약관** | 약관·상품방법서·상품해설서 | 특정 상품의 정확한 보장 답변 | 🔜 **10/1** |
| 고객 계약 | 가입 내역·유지·청구 이력 | 로그인 고객의 "내 보험" | 🔜 연동 |
| **마이데이터** | 타사 보험·건강검진·진료기록 | 보장 전체를 놓고 개인 맞춤 | ⏳ 다음 단계 |

> 마이데이터 연결은 **MediCode가 온전히 작동하기 위한 전제**입니다.
> 그 전까지는 "지금 보이는 것은 확인된 계약 범위"임을 반드시 밝힙니다.

### L2 — 코어 지능 레이어

모든 페르소나가 공유하는 하나의 Insurance Vertical AI™.
그 위에 **정본 계층**이 얹혀 페르소나의 인격이 됩니다.

```
코어 지능 (공유)                 정본 계층 (이 레포)
보험지식·법령·약관·실무    +    Manifesto · Charter · 운영 지침
                                = prompt/insurance-ai.system.md
```

정본은 **어떤 확장에서도 변하지 않는 층**입니다. 바꿔야 한다면 Charter·지침에서 먼저 바꿉니다.

### L3 — 페르소나 & 에이전트 레이어

**두 개의 축이 만나는 층입니다. 혼동하기 쉬우므로 구분합니다.**

| | 축 | 구성 | 고객에게 |
| --- | --- | --- | --- |
| **페르소나** | 고객 가치 (If/When) | insurance AI · MediCode · VFA · HopePlan · Legacy Plan | 보인다 (이름·인격) |
| **에이전트** | 시스템 업무 | 상품(약관) · 계약 · 청구 · 연금 | 보이지 않는다 |

둘은 포함 관계가 아니라 **직교**입니다. MediCode 하나가 답하려면 상품 에이전트와 계약 에이전트를 함께 호출합니다.

**가드레일**: 모든 Tool Calling은 호출 전 검증 레이어를 통과합니다.
보험·금융 도메인 오류의 법적 리스크 방지가 목적이며, [지침 4장](guidelines.md)의 금지사항이 검증 기준입니다.

### L4 — 에이전틱 레이어 (오케스트레이터)

- **의도 분류**: Rule(1차) → LLM(2차) 하이브리드. "암 진단금 나와요?" → 약관 질의로 분류.
- **페르소나 인계 판단**: 주제의 깊이와 축(If/When)을 보고 어느 전문가가 필요한지 결정 → [personas.md](personas.md) 4항
- **모드 전환**: 일반 대화 ↔ 절차형 워크플로우(청구 안내 등)를 결정론적 상태머신으로 전환. 이탈 시 대화로 자동 복귀.
- **컨텍스트**: 멀티턴 이력과 로그인 컨텍스트 유지(Stateful). **인계 시 맥락을 함께 넘겨** 고객이 같은 말을 반복하지 않게 합니다.

### L5 — 서비스 레이어

**B2C** — insurance AI 독립 앱/웹. 고객이 만나는 하나의 얼굴. 대화에서 전문 서비스(메디코드 설계, 청구, 계산기)로 바로 연결.

**B2B** — 보험사·GA를 위한 API Gateway. 테넌트 격리로 고객사별 데이터·지식베이스를 분리 운영. White Label 시 브랜드 표기만 교체되고 **페르소나와 운영 지침은 동일하게 유지**됩니다.

### L6 — 클라이언트 레이어

| | 사용자 | 접점 |
| --- | --- | --- |
| B2C | 보험 계약자·피보험자·예비 고객 | 앱/웹 |
| B2B | 보험사 · GA · Enterprise | API · White Label · 임베드 |

로그인 여부에 따라 답변 범위가 달라집니다(L1 참조).

## 3. 처리 흐름 예시

**"제 암보험, 갑상선암도 진단금 나와요?"** (약관 연결 후)

```
L6 고객 질문
L5 앱: 로그인 확인 → 고객 컨텍스트(가입 내역) 첨부
L4 의도 분류: 보장 여부 질의 → 약관 질의로 판정, insurance AI가 직접 처리(인계 불필요)
L3 상품 에이전트: 해당 약관 검색(Vision PDF·GraphRAG)
     → "소액암 분류·감액 조항" 발견 → 가드레일: 조항 원문 근거 확인 통과
L2 코어 + 정본: 응답 5단 구조로 조립
     ① 결론 (가입 상품 기준 지급 대상 여부)
     ② 근거 (약관 제○조 원문)
     ③ 내 상황의 의미 (가입 시점·감액 기간 반영)
     ④ 불리한 조건 먼저 (소액암 분류 시 감액 지급률)
     ⑤ 다음 행동 (진단서 준비, 청구 절차 확인)
L6 고객: 설명할 수 있는 답을 받음
```

**같은 질문, 약관 연결 전(현재)**
L3에서 약관 원문 부재 → [지침 4-2·5-4] 발동 → **단정하지 않고** "정확한 답은 약관 확인이 필요합니다" +
확인 경로 안내 + 전문가 연결 제안.

**인계가 일어나는 예 — "제 건강 상태에 맞는 보장이 뭘까요?"**
```
L4 의도 분류: 보장 설계 → If 축, 깊이 있음 → MediCode 인계 판단
L3 insurance AI: "보장 설계는 메디코드가 더 정확합니다. 연결해 드릴게요" + 맥락 전달
   MediCode: 의료데이터 분석 → 질병 발생 가능성 → 보장 설계 제안 (④ 생략 없이)
   insurance AI: 결과를 고객 언어로 정리해 마무리
```

## 4. 벨루가 구축과의 대응

| insurance AI 레이어 | 벨루가 To-Be | 이번 차수 |
| --- | --- | --- |
| L5 서비스 | L1 API Gateway (멀티테넌트) | ✅ B2B 테넌트 격리 포함 |
| L4 에이전틱 | L2 오케스트레이터 + L4 모드 전환 | ✅ (상품 라우팅 우선 검증) |
| L3 에이전트 | L3 멀티 도메인 에이전트 | ★ **상품 에이전트만** |
| L2 코어 지능 | L3 가드레일 + L5 지식베이스 | ✅ 이번 차수 핵심 |
| L1 데이터 | L5 지식베이스 + A2 시스템 연동 | 상품DB(약관) 우선 |

> **읽는 법**: 이번 6개월은 insurance AI의 **L2(코어)와 L3(상품 에이전트)를 세우는 공사**입니다.
> 페르소나 4인과 정본은 이 레포에서 이미 완성되어 있으므로, 구축 완료 시 결합만 하면 됩니다.
> 전문 페르소나(HopePlan·Legacy Plan)와 나머지 에이전트는 그다음 차수입니다.

## 5. 확장 원칙

| 확장 대상 | 방법 |
| --- | --- |
| 새 전문 영역 | **L3에 페르소나 추가** + L4 인계 규칙에 조건 추가. 정본은 그대로 상속 |
| 새 업무 기능 | **L3에 에이전트 추가**. 코드 배포 없이 프로필(설정) 기반 |
| 새 데이터 | **L1에 연결** → [지침 5-4] 연결 상태 표와 시스템 프롬프트 9절 갱신 → 프롬프트 버전 ↑ |
| 새 고객사(B2B) | **L5에 테넌트 추가**. 페르소나·지침은 동일, 브랜드 표기만 교체 |
| 정체성·규범 | **L2 정본에서만** 변경. 다른 층에서 새 문장을 만들지 않는다 |
