# Insurance AI — 레이어 구성 (Layer Architecture)

> Insurance AI 관점에서 본 계층 구조입니다. 회사 전체 아키텍처는 [architecture.md](../architecture.md),
> 여기서는 **고객의 질문 하나가 어떤 층을 지나 답이 되는지**를 기준으로 구성합니다.

---

## 1. 전체 구성 — 6개 레이어

```
 L6  고객 (Client)
      「○○○의 Ai Link」 — 담당 FA 이름이 붙은 개인 페이지, QR/카톡 링크로 전달
──────────────────────────────────────────────────────────────
 L5  서비스 (AI Service) — Ai Link Gateway
      인증·로그인 │ 테넌트 격리(고객 채널) │ 대화 UI │ 서비스 연결(메디코드·청구·계산기)
──────────────────────────────────────────────────────────────
 L4  에이전틱 (Agentic) — 마스터 오케스트레이터
      의도 분류(Rule→LLM 2-Tier) │ 에이전트 라우팅 │ 컨텍스트 관리 │ 대화↔워크플로우 모드 전환
──────────────────────────────────────────────────────────────
 L3  전문 에이전트 (Agents)
      상품 에이전트★ │ (계약·청구·연금 에이전트 — 단계적 확장)
      가드레일 내장 Tool Calling: 호출 전 검증 레이어 필수 통과
──────────────────────────────────────────────────────────────
 L2  코어 지능 (Core Intelligence) — Insurance Vertical AI™
      보험지식 │ 보험법령 │ 보험상품 │ 보험약관 │ 보험실무 │ 의사결정 엔진
      + 페르소나 계층: 시스템 프롬프트(정체성·지침) = 이 레포의 정본
──────────────────────────────────────────────────────────────
 L1  데이터 (Data)
      Micky │ BumE_C │ Cloud │ Veluga(10/1~) │ My DATA(향후) │ External MCP
```

★ = 벨루가 6개월 차수의 핵심 구축 범위

## 2. 레이어별 정의

### L1 — 데이터 레이어

Insurance AI가 근거로 삼는 원천. **연결 여부가 곧 답변 범위**입니다 ([지침 5-4](guidelines.md)).

| 데이터 | 내용 | Insurance AI에서의 쓰임 | 상태 |
| --- | --- | --- | --- |
| **Micky DATA** | 보험이론·재무·법령·기관 자료 | 보험 일반 질문의 지식 기반 | ✅ 연결 |
| **BumE_C DATA** | 아이에프에이 고객 안내 데이터 | 회사 서비스·절차 안내 | ✅ 연결 |
| **Cloud DATA** | 가입 내역·서비스 신청 이력 | 로그인 고객의 "내 보험" 조회 | ✅ 연결(로그인 시) |
| **Veluga DATA** | 보험약관·상품방법서·해설서 | 특정 상품의 정확한 보장 답변 | 🔜 **10/1** |
| **My DATA** | 타사 보험·건강검진·진료기록 | 보장 전체를 놓고 개인 맞춤 안내 | ⏳ 다음 단계 |
| **External MCP** | 법령·공공·제휴 데이터 | 법령 근거·공공정보 | ✅ 수시 |

### L2 — 코어 지능 레이어

모든 페르소나가 공유하는 하나의 Insurance Vertical AI™. Insurance AI 고유의 것은 **페르소나 계층**입니다:

```
코어 지능 (공유)               페르소나 (Insurance AI 고유)
보험지식·법령·약관·실무   +   정체성·지침·화법·금지사항
                              = prompt/insurance-ai.system.md
```

같은 코어 위에서 iFA AI(ORCA Ai)는 전문가 페르소나를, Insurance AI는 고객 페르소나를 씁니다.

### L3 — 전문 에이전트 레이어

| 에이전트 | Insurance AI에서의 역할 | 상태 |
| --- | --- | --- |
| **상품 에이전트** | 약관 검색·조항 근거 제시 (역할 3 '약관 번역'의 엔진) | ★ 이번 구축 |
| 계약 에이전트 | 내 계약 조회·관리 (역할 1·5) | 단계적 |
| 청구 지원 | 청구 가능성·서류 안내 (역할 4) | 단계적 |
| 메디코드 연동 | 개인 위험 분석·설계 (역할 2) | 서비스 연결 |

가드레일: 모든 Tool Calling은 호출 전 검증 레이어를 통과합니다. 보험·금융 도메인 오류의 법적 리스크 방지가 목적이며, [지침 4장](guidelines.md)의 금지사항이 검증 기준이 됩니다.

### L4 — 에이전틱 레이어 (오케스트레이터)

- **의도 분류**: Rule(1차) → LLM(2차) 하이브리드. "암 진단금 나와요?" → 상품/약관 질의로 분류.
- **라우팅**: 분류된 의도에 맞는 에이전트 선택. 이번 차수는 상품 에이전트 라우팅 우선 검증.
- **모드 전환**: 일반 대화 ↔ 절차형 워크플로우(예: 청구 안내 단계별 진행)를 결정론적 상태머신으로 전환. 이탈 시 대화로 자동 복귀.
- **컨텍스트**: 멀티턴 대화 이력과 로그인 고객 컨텍스트를 유지(Stateful).

### L5 — 서비스 레이어 (Ai Link)

- Insurance AI가 고객을 만나는 유일한 문. 담당 FA 이름이 붙은 「○○○의 Ai Link」.
- 테넌트 격리: 고객 채널은 FA 채널(ORCA Ai)과 데이터·에이전트·지식베이스가 분리됩니다.
- 대화만이 아니라 **서비스 연결**: 답변 → 메디코드 보험설계·빠른 청구·계산기로 바로 이동.
- 고객의 서비스 사용은 담당 FA에게 표시 → FA가 먼저 연락하는 구조.

### L6 — 클라이언트 레이어

보험 계약자·피보험자·예비 고객. 로그인 여부에 따라 답변 범위가 달라집니다(L1 참조).

## 3. 처리 흐름 예시

**"제 암보험, 갑상선암도 진단금 나와요?"** (10/1 약관 연결 후)

```
L6 고객 질문
L5 Ai Link: 로그인 확인 → 고객 컨텍스트(가입 내역) 첨부
L4 의도 분류: 보장 여부 질의 → 상품 에이전트 라우팅
L3 상품 에이전트: 해당 상품 약관 검색(Vision PDF·GraphRAG)
     → "소액암 분류·감액 조항" 발견 → 가드레일: 조항 원문 근거 확인 통과
L2 코어+페르소나: 응답 5단 구조로 조립
     ① 결론(가입 상품 기준 진단금 지급 대상 여부)
     ② 근거(약관 제○조 원문)
     ③ 내 상황 의미(가입 시점·감액 기간 반영)
     ④ 불리한 조건 먼저(소액암 분류 시 감액 지급률)
     ⑤ 다음 행동(진단서 준비, 담당 FA 청구 확인)
L6 고객: 설명할 수 있는 답을 받음
```

**같은 질문, 약관 연결 전(현재)**: L3에서 약관 원문 부재 → [지침 4-2·5-4] 발동 →
"정확한 답은 약관 확인이 필요합니다" + 확인 경로 + 담당 FA 연결 제안. **단정하지 않습니다.**

## 4. 벨루가 구축과의 대응

| Insurance AI 레이어 | 벨루가 To-Be | 이번 차수 |
| --- | --- | --- |
| L5 서비스 | L1 API Gateway (멀티테넌트) | ✅ |
| L4 에이전틱 | L2 오케스트레이터 + L4 모드 전환 | ✅ (상품 라우팅 우선) |
| L3 에이전트 | L3 멀티 도메인 에이전트 | ★ 상품 에이전트만 |
| L2 코어 지능 | L3 가드레일 + L5 지식베이스 | ✅ 핵심 |
| L1 데이터 | L5 지식베이스 + A2 시스템 연동 | 상품DB(Veluga) 우선 |

> **읽는 법**: 이번 6개월은 Insurance AI의 L2(코어)와 L3(상품 에이전트)를 세우는 공사입니다.
> 페르소나(시스템 프롬프트)는 이 레포에서 이미 완성되어 있으므로, 구축 완료 시 바로 결합합니다.

## 5. 확장 원칙

- 새 역할(청구·연금·상속)은 **L3에 에이전트를 추가**하는 방식으로 확장합니다. 코드 배포 없이 프로필(설정) 기반.
- 새 데이터는 **L1에 연결**하고, [지침 5-4]의 연결 상태 표와 시스템 프롬프트 9절을 갱신한 뒤 프롬프트 버전을 올립니다.
- 페르소나(정체성·지침)는 어떤 확장에서도 **변하지 않는 층**입니다. 바뀌어야 한다면 정본(Charter·지침)에서 먼저 바꿉니다.
