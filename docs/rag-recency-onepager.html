상품 질문에 옛날 자료가 섞이는 문제

대상 · 원수사이슈 등 월간 스냅샷 문서
작성 · 2026-08-18 · v1

프롬프트 문제가 아니라 인덱스에 시점 정보가 없어서 생기는 문제입니다. 2023년 청크와 2025년 청크가 유사도만 높으면 똑같은 자격으로 컨텍스트에 들어가고, 모델은 어느 쪽이 최신인지 알 방법이 없어 둘 다 사실로 씁니다.

해결의 핵심은 생성 단계가 아니라 검색 단계에서 오래된 청크를 애초에 넣지 않는 것입니다.

진단

원인 세 가지

CAUSE 01

청크에 기준시점이 없다

파일명의 202509가 메타로 파싱되지 않고 파일명으로만 남아 있습니다. 검색도 생성도 시점을 못 봅니다.

CAUSE 02

스냅샷 문서가 누적된다

월간 이슈 문서는 매달 같은 사실을 반복 기술합니다. 12개월치면 동일 내용 청크가 12개, 그중 오래된 게 걸립니다.

CAUSE 03

판매중지 상품이 살아 있다

폐지·중지 상품이 인덱스에 그대로 남아 "현재 판매 중"처럼 답변됩니다. 상품 질문에서 가장 치명적입니다.

처방

네 단계

1 → 2 순서로 약 2일. 2단계가 증상을 직접 잡습니다
STEP 1 · 적재 1일

메타데이터 부여

모든 청크에 as_of doc_type status entity를 붙입니다.

본문 맨 앞에 텍스트로도 박아 넣으세요. 메타 필드로만 두면 임베딩에도 생성에도 반영되지 않습니다.

STEP 2 · 검색 핵심

엔티티 단위 최신본만

  • 기본은 현행 조회 — 최근 6~12개월 + status=current
  • "예전 · 추이 · 변경 · 연도 명시" → 전 기간
  • entity로 묶어 최신 as_of만 채택
STEP 3 · 생성 0.5일

충돌 처리 규칙

정리 후에도 남는 충돌을 프롬프트로 마무리합니다. 최신 우선, 과거는 시점 표기 필수, 시점이 다른 내용을 한 문장에 섞지 않기.

STEP 4 · 출력 0.5일

답변에 시점 노출

회사 이름 옆의 날짜 배지 하나가 "보완 후 답변" 기능보다 실질적으로 더 큰 역할을 합니다. 사용자가 스스로 판단할 수 있게 됩니다.

핵심 · 엔티티 dedup 이 하는 일

검색 직후 — 같은 상품, 다른 시점이 공존
악사·당뇨 2025-09 악사·당뇨 2023-04 우체국 2025-09 DB·CI 2023-04
group by entity → max(as_of)
컨텍스트 투입 — 상품당 한 시점만
악사·당뇨 2025-09 악사·당뇨 2023-04 우체국 2025-09 DB·CI 2023-04

최신본이 있는 상품은 과거 청크를 버리고, 과거 자료밖에 없는 상품(DB·CI)은 남기되 과거 표시를 달아 넘깁니다. 버리지 않고 라벨링하는 게 요점입니다.

메타 스키마 · 본문 프리픽스

// 청크 메타
{
  "as_of":  "2025-09",          // 파일명·시트에서 파싱
  "doc_type": "monthly_issue",
  "status": "current",         // superseded | discontinued
  "entity": "악사손해보험/당뇨전용건강보험"
}

// 청크 본문 — 이 한 줄이 임베딩·생성 양쪽에 먹힙니다
[2025-09 기준 | 영업기획팀 원수사이슈]
악사손해보험 — 당뇨 전용 건강보험 언급 ...

프롬프트 규칙

각 자료에는 [YYYY-MM 기준] 표기가 있습니다.

1. 같은 회사·상품에 시점이 다른 내용이 있으면
   가장 최근 자료만 사실로 삼고 과거는 제외합니다.
2. 과거 자료만 있는 항목은 반드시
   "(2023-04 기준, 현재 판매 여부 미확인)"
   처럼 시점을 붙여 표기합니다.
3. 시점이 다른 내용을 한 문장에 섞지 않습니다.
4. 답변 첫 줄에 "기준: YYYY-MM"을 씁니다.

  • 판매중지 목록을 별도 테이블로 관리하고 status만 바꾸세요. 문서를 지우면 이력 질문에 답할 수 없습니다.
  • 파일명 파싱 규칙을 고정하세요. 202509 2025-09 25년9월이 섞이면 as_of가 비고, 비는 순간 필터를 그냥 통과합니다.

  • 골든셋 20~30문항으로 회귀 검증. "지금 판매 중인 X", "언제부터 바뀌었나", "작년 기준 Y" 세 유형을 섞으세요.
우선순위

하나만 고른다면 2단계

같은 상품의 시점 다른 청크가 동시 투입되는 것만 막아도 증상 대부분이 사라집니다
순위할 일효과비용비고
1 청크 메타 부여 + 본문 시점 프리픽스 ●●●●● 1일 2단계의 전제 조건. 이것부터
2 엔티티 dedup + 현행/이력 라우팅 ●●●●● 1일 증상을 직접 해결하는 단계
3 판매중지 상태 테이블 연동 ●●●●● 2~3일 영업기획팀 데이터 협의 필요
4 프롬프트 규칙 + 답변 포맷 ●●●●● 1일 1·2 없이 단독 적용하면 효과 제한적
5 월간 문서 diff 인덱싱 ●●●●● 1주+ 중복 급감. 파이프라인 개편 동반
