# 건보 데이터 연동 흐름 (메모)

출처: CX 마케팅팀 카카오톡 대화 (유성 매니저 설명, 오후 2:56~2:57)
기록일: 2026-08-26

> 원문 그대로: "아마도 이런 과정일껄로 알고 있습니다."
> → 확정된 스펙이 아니라 **전언 기준의 추정 흐름**임. 아래 체크리스트로 검증 필요.

## 파이프라인

```
ifa
 └─▶ 스크래핑업체
       └─▶ 건보데이터 (10년치 + 투약정보)
             └─▶ ifa
                   └─▶ 메디에이지 데이터 추가 및 정리
                         └─▶ ifa
```

단계별 정리:

| # | 단계 | 주체 | 산출물 |
|---|------|------|--------|
| 1 | 스크래핑 요청 | ifa → 스크래핑업체 | 조회 요청 |
| 2 | 건보 데이터 수집 | 스크래핑업체 | 10년치 건보 데이터 + 투약정보 |
| 3 | 수집 결과 반환 | 스크래핑업체 → ifa | 원본 데이터 |
| 4 | 데이터 보강·정리 | 메디에이지 | 가공 데이터 |
| 5 | 최종 반환 | 메디에이지 → ifa | 정리된 데이터 |

## 확인된 사실

- **투약정보는 건보 데이터에 함께 실려서 온다.** 별도 소스가 아님.
- **건보 투약정보 ≠ 교보라플.** 서로 다른 건이므로 같은 소스로 취급하면 안 됨.
- 건보 데이터 조회 범위는 **10년치**.

## 연동 점검 체크리스트

아직 검증되지 않은 항목들. 실제 시스템/코드가 확인되면 하나씩 채울 것.

- [ ] 스크래핑업체 연동 방식 (API / 배치 / 파일 전달?) 및 인증 수단
- [ ] 건보 데이터 응답 스키마 — 투약정보가 실제로 동일 페이로드에 포함되는지
- [ ] 10년치 조회 시 페이징·기간 분할 필요 여부, 응답 지연/타임아웃
- [ ] ifa → 메디에이지 전달 방식과 메디에이지 가공 결과 반환 방식
- [ ] 각 구간 실패 시 재시도·정합성 확인 로직 존재 여부
- [ ] 교보라플 데이터와 건보 투약정보가 코드/DB 상에서 분리되어 있는지
- [ ] 개인정보(민감정보) 처리 — 전송 구간 암호화, 보관 기간, 동의 범위
