# 제품 정의

## 무엇을 대체하는가

**FA가 선배 설계사나 지점장에게 확인하던 것을 대체한다.**

경쟁 상대는 다른 약관 검색 AI가 아니라 **사람에게 묻는 방식**이다. 그 방식의 문제는 셋이다.

- 물어볼 수 있는 시간이 정해져 있다 (상대가 응대 가능할 때만)
- 답이 사람에 따라 다르다 (선배의 기억과 경험에 의존)
- 묻는 쪽이 아쉬워진다 (자주 묻기 어렵다)

이 서비스는 **24시간, 같은 기준으로, 눈치 보지 않고** 물을 수 있게 한다.
그러므로 「모홈보다 검색이 낫다」가 아니라 **「선배에게 묻는 것보다 낫다」**가 성공 기준이다.
답의 근거를 조항으로 보여주는 이유도 여기 있다 — 사람의 기억보다 나으려면 근거가 있어야 한다.

가장 크게 도움이 되는 영역은 **보상**이다. 지급 여부는 기억으로 답하기 가장 위험한 영역이고,
틀리면 고객에게 잘못 안내한 것이 된다.

## 시작 범위 — 두 소스뿐

```
Micky DATA   보험 일반지식        → 범용 질문에 답한다
VELUGA       약관 데이터          → 상품 · 판별 조항으로 답한다
```

**시작은 이 둘만이다.** 보장분석 · Cloud DATA · External MCP는 시작 범위에 없다.
초개인화(아래)는 보장분석이 붙은 뒤에 열리는 단계이며, 그 전까지는 범용 답변으로 동작한다.

## 답변 두 층

### 1층 — 범용 (Micky + 약관)

담보 용어, 제도, 일반적인 지급 기준. 계약 정보 없이 답할 수 있는 범위다.

> 「골절진단비가 뭔가요?」 → 약관 공통 정의
> 「음주운전 사고도 지급되나요?」 → 해당 상품 · 판의 면책 조항

이 층에서는 **금액을 말하지 않는다.** 약관은 가입 가능한 담보의 목록일 뿐,
이 계약이 무엇에 얼마 가입했는지는 담고 있지 않다.

### 2층 — 초개인화 (+ 보장분석)

「어디가 다쳤는데 얼마 받을 수 있어요」에 답하는 층이다. 성립 조건이 명확하다.

| 필요한 것 | 출처 |
| --- | --- |
| 어느 보험사 · 어느 상품 | 보장분석 |
| 가입 담보와 **가입금액** | 보장분석 |
| 적용 약관 판 | 계약년월 → 판 매핑 |
| 지급사유 · 면책 · 감액 조항 | 약관 |

**넷 중 하나라도 없으면 금액을 말하지 않는다.**
특히 가입금액이 없으면 「가입했다면 얼마」조차 말할 수 없다.

## 면책이 먼저다

이 제품에서 가장 위험한 오답은 **지급되지 않는 건을 「나온다」고 답하는 것**이다.
지급사유 조항만 보면 보상 가능해 보이지만, 면책 조건에 해당하면 지급되지 않는다.

그래서 판정 순서를 코드로 고정했다(`src/orca/payout.py`).

```
1. 가입했는가        → 아니면 약관을 볼 필요가 없다
2. 면책에 걸리는가    → 걸리면 거기서 끝. 지급사유가 있어도 뒤집지 못한다
3. 지급사유가 있는가  → 없으면 「모른다」. 없는 근거를 만들지 않는다
4. 감액 · 대기기간 · 한도가 있는가 → 있으면 확정 금액을 말하지 않는다
```

**답변에서도 판정 결과가 맨 앞에 온다.** 지급사유를 먼저 보여주면 FA가 그 줄에서
읽기를 멈추고, 아래 면책은 읽히지 않는다.

면책 · 미가입일 때 금액 자리에 **0원을 쓰지 않는다.** 0원은 계산 결과처럼 보이지만
실제로는 지급 자체가 성립하지 않는 것이므로, 숫자가 아니라 사유를 둔다.

### 약관 색인에서 면책이 우선이다

벤더 등록 · 색인 품질을 볼 때도 면책 조항이 기준이다.
지급사유는 잘 찾는데 면책을 놓치는 색인은 **가장 나쁜 형태로 틀린다.**
등록 후 검수(원 질문 재실행)에서 면책 조항이 함께 나오는지를 통과 조건으로 삼는다.
