# 표준약관 7개 — 원본 반입 및 분할 가이드

벨루가 검증용 30개 구성 중 **표준약관 7개**를 만드는 절차입니다.
`표준약관 7개 + 최근 판매상품 약관 23개` 의 앞쪽 7개에 해당합니다.

## 0. 왜 사용자가 직접 내려받아야 하나

이 세션의 실행 환경은 아웃바운드 접속이 허용 목록으로 제한되어 있습니다.
`www.law.go.kr`, `www.fss.or.kr`, `www.knia.or.kr` 모두 프록시에서 **403(CONNECT 거부)** 로
차단되는 것을 확인했습니다. 따라서 원본 PDF는 사용자가 내려받아 전달해야 하고,
전달 이후의 분할·검증·커밋은 이 저장소의 도구가 자동으로 처리합니다.

## 1. 내려받을 원본 (딱 한 개)

| 항목 | 값 |
|---|---|
| 근거 | 보험업감독업무시행세칙 **[별표 15] 표준약관** |
| 시행 | 2026. 9. 10. |
| 개정 | 2026. 8. 28. 일부개정 |
| 출처 | 국가법령정보센터(law.go.kr) → `보험업감독업무시행세칙` → **별표·서식** 탭 → `[별표 15] 표준약관` → PDF 내려받기 |

> 7개 파일을 각각 찾아 받는 것이 아닙니다. **[별표 15] 한 개 PDF 안에 7종이 모두 들어 있고**,
> 이 저장소의 도구가 그것을 종목별로 나눕니다. 이 방식이라야 7종의 시행일·개정 이력이
> 서로 어긋나지 않고 한 시점으로 정렬됩니다.

## 2. 전달 방법 (둘 중 하나)

- **A. 대화에 첨부** — Claude 대화창에 PDF를 그대로 올립니다.
- **B. Google Drive 업로드** — Drive에 올린 뒤 파일명을 알려주시면 이 세션에서 받아옵니다.

받은 파일은 `input/` 에 둡니다. 이 폴더의 PDF는 용량 때문에 커밋하지 않습니다.

## 3. 분할 실행

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# (1) 제목이 어느 쪽에서 잡히는지 눈으로 확인
.venv/bin/python tools/split_standard_terms.py input/별표15_표준약관_20260910.pdf --detect

# (2) 분할 계획(쪽 범위)만 확인
.venv/bin/python tools/split_standard_terms.py input/별표15_표준약관_20260910.pdf --dry-run

# (3) 실행 → standard_terms/20260910/ 에 7개 PDF + split_manifest.json
.venv/bin/python tools/split_standard_terms.py input/별표15_표준약관_20260910.pdf \
    -o standard_terms/20260910
```

자동 판별이 어긋나면 `tools/ranges.example.json` 형식으로 쪽 범위를 직접 지정합니다.

```bash
.venv/bin/python tools/split_standard_terms.py input/원본.pdf \
    -o standard_terms/20260910 --ranges ranges.json
```

원본이 스캔 이미지(페이지에 텍스트가 없음)이면 자동 판별이 불가능하므로 `--ranges` 가 필수입니다.

원문 동일성을 제3자에게 증빙해야 할 때 이 파일을 함께 제시합니다.

## 5. 원문 보존 원칙

- 페이지 객체를 **그대로 복사**합니다. 텍스트·표·서식을 재작성하지 않습니다.
- 원본 페이지가 빠짐·겹침 없이 정확히 한 번씩 7개 파일에 나뉘는지 자동 검증합니다.
- 별표 첫머리의 표지·목차 쪽은 기본적으로 어느 파일에도 넣지 않습니다
  (`--prefix-to-first` 로 1번 파일에 포함 가능).

## 6. 도구 자체 검증

원본 없이도 도구가 정상인지 확인할 수 있습니다. 구조만 흉내낸 합성 PDF로 검증합니다.

```bash
.venv/bin/python -m pytest -q tests
```

현재 이 브랜치에서 **5개 테스트 전부 통과**를 확인했습니다.
