# 교보라이프플래닛 계약 제안서 검토

- 작성일: 2026-08-26
- 대상: 바른플랜 SaaS(내보험조회) API 연동 계약 제안
- 계약 주체: 인슈어런스AI ↔ 교보라이프플래닛

---

## 0. 총평

**구조는 적법하게 설계 가능한 형태입니다.** 앞선 검토에서 우려한
"허가 대여 / 데이터 구매" 구조가 아니라 **SaaS 이용 계약**이며,
GA 2개사 선례가 있어 교보 측 컴플라이언스 검토를 거친 것으로 보입니다.

다만 **체크포인트 항목 2개가 계약서상 근거 없이는 실행 불가**하며,
**할인 구간이 사실상 도달 불가능하게 설계**되어 있습니다.

| 구분 | 판정 |
|---|---|
| 계약 구조 (SaaS 이용) | ✅ 적법 설계 가능 |
| 학습 데이터 활용 | 🔴 계약·동의 근거 확인 필수 |
| 라플 앱 DB 제공 | 🔴 제3자 제공 동의 확인 필수 |
| 비용 구조 | ⚠️ 감당 가능하나 할인 구간 비현실적 |
| 계약 조건 | ⚠️ 핵심 조항 다수 누락 |

---

## 1. ✅ 좋아진 점 — 구조가 명확해졌습니다

### 1.1 데이터 구매가 아니라 SaaS 이용입니다
- "바른플랜 SaaS API 연동" = 교보의 **서비스를 이용**하는 것
- 앞서 우려한 "월 사용료 내고 데이터를 산다"는 구조가 아님
- 비용 항목이 **구축비 + 월고정비 + 호출당 사용료**로 구성 → 전형적 SaaS 과금

### 1.2 시장 선례가 존재합니다
- GA 2개사가 동일 조건으로 사용 중
- 교보가 이미 내부 컴플라이언스를 통과시킨 구조일 가능성이 높음
- **다만 회사명 비공개** → 직접 검증 불가

### 1.3 확인 필요 — 바른플랜의 데이터 소스
| 소스 | 적용 규율 |
|---|---|
| 마이데이터(전송요구권) 기반 | 신용정보법 마이데이터 규율 전면 적용 |
| 신용정보원 내보험찾아줌 연계 | 다른 규율, 상대적으로 단순 |

**어느 쪽인지에 따라 동의·재제공 제약이 크게 달라집니다. 최우선 확인 항목.**

---

## 2. 🔴 위험 1 — "메디코드 AI 개발 시 학습 데이터 활용 용이"

제안서 체크포인트에 명시된 문구입니다. **이건 별도 근거 없이는 불가합니다.**

### 왜 문제인가
- SaaS 이용 과정에서 접근한 개인신용정보를 **AI 학습에 쓰는 것은 목적 외 이용**
- 위탁 구조라면 **위탁 범위를 벗어남** (위탁은 위탁자 업무 수행 목적만 허용)
- 학습에 쓰려면 원칙적으로 **가명처리** 필요
- 마이데이터 수집정보라면 추가 제약

### 확인 사항
- [ ] 계약서에 **학습 데이터 활용 권한이 명시**되어 있는가
- [ ] 고객 동의서에 **AI 학습 목적 이용 항목**이 포함되어 있는가
- [ ] 가명처리 주체와 방식이 정해져 있는가
- [ ] 학습 결과물(모델)의 **소유권**이 누구에게 있는가

> **제안서에 적혀 있다는 것만으로는 근거가 되지 않습니다.**
> 계약서 조항과 고객 동의서 문구를 직접 확인해야 합니다.

---

## 3. 🔴 위험 2 — "라플 앱 정보에 따른 DB 생성 및 제공"

> 앱 사용자의 이력에 따른 **보험관심별로 DB 제공** (iFA 판매건)

### 왜 문제인가
- **"DB 제공" = 개인정보 제3자 제공**입니다
- 마케팅 목적 제3자 제공은 **정보주체의 명시적 별도 동의**가 필수
- **제공받는 자(인슈어런스AI)도 책임 주체**입니다 — 교보가 동의를 안 받았어도 함께 문제됩니다
- 보험업계에서 DB 제공은 제재 사례가 누적된 민감 영역

### 확인 사항
- [ ] 교보가 해당 DB를 제공할 **적법 근거(고객 동의)를 보유**하는가
- [ ] 동의서에 **"제3자 제공" 및 제공받는 자**가 특정되어 있는가
- [ ] "보험관심별 분류"가 **프로파일링**에 해당하는지
- [ ] 제공 후 인슈어런스AI의 **보유·파기 정책**

> 동의서 문구 원문을 요구해서 직접 확인하십시오.
> 계약서에 "교보가 적법하게 취득한 동의에 기반한다"는 **진술보장 조항**을 넣어야 합니다.

## 4. 💰 비용 구조 분석

### 4.1 계약 조건 (VAT 포함)
| 항목 | 금액 |
|---|---|
| 구축비 (일회성) | 54,559,400원 |
| 월 고정비 | 5,500,000원 |
| 월 사용료 | 110원/건 — 월 5만건 무료, 초과 100원/건 |
| 특별 조건 | 월사용료 6개월 무료 |

### 4.2 1년차 총비용
| 항목 | 금액 |
|---|---|
| 구축비 | 54,559,400 |
| 월고정비 × 12 | 66,000,000 |
| 월사용료 | 0 (6개월 무료 + 5만건 이내) |
| **합계** | **약 1억 2,056만원** |

### 4.3 ⚠️ 할인 구간이 비현실적입니다
장기보험 판매건수 구간별 월고정비 할인 (20건 10% ~ 120건 이상 100%)

| 월 판매 | 할인율 | 월 부담 | 연 부담 |
|---|---|---|---|
| 0건 | 0% | 550만 | 6,600만 |
| 20건 | 10% | 495만 | 5,940만 |
| **40건** (토스 수준) | ~28%* | 396만 | 4,752만 |
| 120건 이상 | 100% | 0 | 0 |

\* 중간 구간이 제안서에 **미명시** — 선형 가정

**제안서 스스로 "토스가 월 30~50건"이라고 밝히고 있습니다.**
토스 규모에서 30~50건이면 **120건은 사실상 도달 불가 구간**입니다.
→ 100% 할인은 마케팅 문구에 가까우며, **중간 구간표를 반드시 받아야 합니다.**

### 4.4 그래도 경제성 자체는 나쁘지 않습니다
월고정비 550만원 회수에 필요한 장기보험 판매건수:

| 건당 수수료 | 월 필요 건수 |
|---|---|
| 50만원 | 11건 |
| 100만원 | 6건 |
| 150만원 | 4건 |

**월 5~10건만 전환돼도 월고정비는 회수됩니다.** (판매수수료는 할인과 별도 수취)
→ 진짜 리스크는 비용이 아니라 **보장분석 → 장기보험 전환율**입니다.

### 4.5 "건"의 정의를 확인해야 합니다
월 5만건 무료가 실제로 커버하는 **고객 수**가 달라집니다.

- API 호출 1회 = 1건인가
- 고객 1명 조회 = 1건인가
- 고객 1명 × 보험사 수 = N건인가

**마지막이면 5만건은 생각보다 빨리 소진됩니다.**

## 5. 🤝 협상 포인트

| # | 항목 | 요구안 |
|---|---|---|
| 1 | 구축비 5,455만원 | 조정 불가라면 **분할 납부** 또는 **성과 연동** |
| 2 | 할인 구간 | **중간 구간표 요구** + 50건 50% 수준으로 재설계 |
| 3 | 월사용료 무료 기간 | 6개월 → **12개월** (전환율 검증 기간 확보) |
| 4 | 초기 부담 | 월고정비 **3~6개월 유예** (구축·안정화 기간) |
| 5 | 최소 계약기간 | 확인 후 **중도 해지권** 확보 |
| 6 | 학습 데이터 | 활용 권한 **계약서 명문화** (적법성 확보 전제) |
| 7 | DB 제공 | 교보의 **동의 취득 진술보장** 조항 삽입 |

> 구축비·월고정비는 "타사 형평성"으로 조정 불가라고 못박았으나,
> **무료 기간 연장과 할인 구간 재설계는 형평성 논리를 우회할 수 있는 협상 여지**입니다.

## 6. 제안서에 없는데 반드시 확인할 항목

- [ ] **계약 기간** 및 자동 갱신 조건
- [ ] **중도 해지 조건 및 위약금** ← 전환율 미달 시 탈출구
- [ ] **데이터 처리 위치** (교보 환경 vs 인슈어런스AI 환경)
- [ ] **위탁계약서** 별도 체결 여부 및 감독 조항
- [ ] **고객 동의서 원문** — 누가, 어떤 범위로 받는가
- [ ] **바른플랜 데이터 소스** (마이데이터 vs 신용정보원)
- [ ] **SLA** 및 장애 시 책임 범위
- [ ] **계약 종료 시 데이터 반환·파기** 절차
- [ ] "건"의 정의
- [ ] 서비스 화면상 **브랜드 표기** (누구의 서비스로 보이는가)
- [ ] GA 2개사의 **컴플라이언스 구조** (익명화해서라도 요구)

## 7. 결론

**계약 자체는 진행 가능한 구조입니다.** 다만 순서가 중요합니다.

1. **먼저** 바른플랜 데이터 소스 + 고객 동의서 원문 확보
2. **그 다음** 학습 데이터·DB 제공의 적법 근거 확인
3. **그 위에** 할인 구간·무료 기간·해지권 협상
4. **마지막에** 서명

**체크포인트에 적힌 "학습 데이터 활용"과 "DB 제공"을 사업계획의 전제로 삼지 마십시오.**
계약서와 동의서에 근거가 없으면 두 항목은 실행할 수 없으며,
이 둘을 빼고도 사업이 성립하는지를 먼저 확인해야 합니다.
