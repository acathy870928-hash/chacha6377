# 되묻기 설계 (상품 · 약관 판 특정)

보상 질문은 **어느 상품의 어느 약관 판인지**가 정해져야 정확한 답이 나온다.
계약 정보(Cloud DATA)가 이번 범위 밖이므로, 그 특정을 **FA에게 되물어** 해결한다.
FA는 상품 · 특약 · 가입 시점을 알고 있으므로 이 방식이 실제로 동작한다.

## 대원칙: 필요할 때만 되묻는다

되묻기는 정확도를 올리지만 매번 하면 도구를 안 쓰게 만든다.
**되묻지 않아도 되는 경우를 먼저 걸러내는 것**이 설계의 핵심이다.

## 되묻기 판단

| 질문 유형 | 예시 | 소스 | 되묻기 |
| --- | --- | --- | --- |
| 일반 지식 · 개념 | 「글라이드패스가 뭔가요?」 | Micky | ❌ 불필요 |
| 상품 일반 설명 | 「오토파일럿 변액연금 어떤 상품이야?」 | VELUGA | ❌ 상품이 이미 특정됨 |
| **보상 · 지급 여부** | 「음주운전 사고인데 보험금 나오나요?」 | VELUGA | ✅ **필요** |
| 보상 + 상품 명시 | 「○○암보험 3판, 갑상선암 진단금 나오나요?」 | VELUGA | ❌ 이미 특정됨 |

즉 **「보상성 질문」이면서 「상품이 특정되지 않은」 경우에만** 되묻는다.

## 되묻기를 생략하는 조건

아래 중 하나라도 해당하면 되묻지 않고 바로 진행한다.

1. 질문에 보험사 · 상품명이 이미 들어 있다
2. **직전 대화에서 이미 특정했다** — 한 상담 중에는 상품이 유지되는 경우가 대부분이다.
   한 번 특정한 상품·판은 세션 컨텍스트로 들고 가며, 매 질문마다 다시 묻지 않는다.
   (FA가 상품을 바꿔 말하면 그때 갱신한다)
3. 약관과 무관한 개념 질문이다 (Micky로 라우팅)

## 무엇을 되묻는가

특정에 필요한 값은 세 가지지만, **한 번에 다 묻지 않는다.**

| 값 | 필요도 | 처리 |
| --- | --- | --- |
| 보험사 · 상품명 | 필수 | 먼저 묻는다 |
| 약관 판 · 시행일 (가입 시점) | 필수 | 상품 특정 후, 해당 상품에 판이 여러 개일 때만 묻는다 |
| 특약 | 질문에 따라 | 담보가 특약에만 있는 경우에 묻는다 |

판을 항상 묻지 않는 이유: 개정 이력이 없는 상품이면 물을 필요가 없다.
벤더 인덱스에서 상품별 판 목록을 받아 **둘 이상일 때만** 되묻는다.

## 되묻는 방식

- **선택지를 제시한다.** 자유 입력으로 두면 상품명 표기가 제각각이라 검색이 흔들린다.
  벤더 인덱스에 있는 상품명을 후보로 제시하고 고르게 한다.
- 모바일 화면이므로 칩(chip) 형태 버튼이 적합하다. (기존 Orca AI 추천 질문 UI와 동일한 형태)
- 후보가 많으면 FA가 입력한 키워드로 좁힌 뒤 제시한다.
- **되묻기는 한 번으로 끝낸다.** 두세 번 연속으로 물으면 그냥 약관 PDF를 여는 게 빨라진다.

## 특정되지 않은 채 답해야 할 때

FA가 되묻기에 답하지 않거나 「그냥 일반적으로 알려줘」라고 하는 경우가 있다.
이때 **임의로 최신 판을 골라 답하지 않는다.** 대신:

- 일반론임을 명시하고, 상품마다 다를 수 있음을 함께 밝힌다
- 어느 기준으로 답한 것인지 표시한다
- 실제 건은 해당 계약의 약관으로 확인이 필요하다고 안내한다

## 대화 예시

**되묻기가 필요한 경우**

```
FA   : 음주운전 사고인데 보험금 나와요?
Orca : 상품에 따라 면책 범위가 다릅니다. 어느 상품 기준으로 볼까요?
       [○○종합보험] [○○운전자보험] [직접 입력]
FA   : ○○운전자보험
Orca : (해당 약관의 지급사유 + 면책 조항을 함께 제시, 근거 조항 인용)
```

**되묻지 않는 경우**

```
FA   : 글라이드패스가 뭔가요?
Orca : (Micky로 라우팅, 바로 답변)
```

```
FA   : (직전에 ○○운전자보험으로 특정한 상태)
       그럼 무면허는요?
Orca : (같은 상품 컨텍스트 유지, 바로 답변)
```

## 미확정 사항

- 상품 후보 목록을 벤더 API에서 받을 수 있는지 (상품 목록 조회 엔드포인트 유무)
- 벤더 API가 멀티턴을 이어받는지, 단발 호출인지
  → 단발이면 세션 컨텍스트는 전부 우리 쪽에서 관리한다
