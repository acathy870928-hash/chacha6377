## 0. 한 줄 요약

연금설계는 **"계산은 정형 엔진, 설명은 AI, 결과는 저장된 플랜"** 세 조각으로 만든다.
1차(10월 오픈)는 설계사가 고객 앞에서 5분 안에 **3층 연금 합산 → 노후 생활비 부족액 → 매월 준비액**을 보여주는 입력 기반 계산기 + AI 설명이다. 마이데이터·VFA 연동은 어댑터 자리만 만들어 두고 2차로 미룬다.

## 2. 설계 원칙 다섯 가지

1. **결정론(Determinism)**: 같은 입력과 같은 가정값 버전이면 항상 같은 숫자. LLM은 숫자를 만들지 않고 엔진 결과를 받아 설명만 한다. (상속증여 계산기·VFA 챗봇에서 검증된 패턴)
2. **가정값은 데이터, 코드가 아니다**: 생활비 기준, 조기·연기 감액률, 기대수명 기본값, 실질수익률 기본값은 버전이 붙은 상수 테이블로 관리한다. 플랜에는 계산에 쓴 가정값 버전을 함께 저장한다.
3. **플랜 객체가 단일 진실**: 채팅에서 바꾸든 설정 화면에서 바꾸든 같은 플랜 객체를 갱신하고 재계산한다. 8/31 회의의 "대화 vs 선택 화면" 질문은 둘 다 허용하되 상태를 하나로 둔다.
4. **모르는 값은 묻지 말고 기본값으로 먼저 보여준다**: 필수 입력은 5개(가구 형태, 현재 나이, 은퇴 나이, 국민연금 예상액, 퇴직·개인연금 정보)로 제한한다. 나머지는 기본값으로 계산하고 결과 카드에서 바꾸게 한다.
5. **추천보다 진단**: 1차는 부족액 진단까지. 상품 추천은 판매중 상품 마스터와 연결된 뒤에만 연다. (8/18 답변품질 시트에서 판매 종료 상품을 추천한 사례 확인)

## 3. 기능 범위

### 1차 (10월 오픈 목표)

| 기능 | 내용 |
|---|---|
| 3층 연금 합산 | 국민연금(조회값 입력) + 퇴직연금(DC·IRP 적립금 또는 DB 예상액) + 개인연금(연금저축·연금보험 예상액 또는 적립금) |
| 국민연금 수령 시점 비교 | 정상 개시연령 기준으로 조기(최대 5년, 연 6% 감액)·연기(최대 5년, 연 7.2% 증액) 시나리오 표 |
| 노후 생활비 갭 | 목표 생활비(패널조사 기준 또는 직접 입력) − 월 연금 합계 → 월 부족액, 총 부족액, 매월 준비액 |
| 은퇴 시점 시나리오 | 은퇴 나이 60/62/65/70 비교표 |
| AI 설명 | 결과 카드를 사람 말로 풀어 설명, 개념 질문은 RAG 답변 |
| 플랜 저장 | 설계사 계정 아래 고객별 플랜 저장, 재조회, 입력 변경 후 재계산 |

### 2차 (오픈 후 1~2개월)

- 마이데이터 연금 정보 어댑터: 가입 연금·연금보험 목록을 자동으로 입력값에 채움 (연금 관련 데이터만 전달)
- VFA 연동: 변액연금 계약의 수익률 시뮬레이션 결과를 개인연금 항목으로 가져옴
- 고객 모드: 설계사가 공유한 플랜을 고객이 열람하는 읽기 전용 화면
- 기대여명 반영: 통계청 완전생명표로 90세 고정을 대체
- 세금·건강보험료 설명: 연금소득세, 종합과세 기준, 퇴직 후 지역가입자 건보료를 RAG로 설명 (계산은 3차)

### 3차

- 정기 포트폴리오 제공 주기 설정(90일·60일 등)과 VFA 리밸런싱 신호 연결
- 세후 연금액 계산, 부부 합산 설계
- 판매중 상품 마스터와 연결된 연금상품 제안

## 4. 사용자 흐름 (설계사 모드)

```
[플러스 메뉴] 연금설계 선택
   ↓
[입력 화면] 5개 필수 + 접힌 고급 옵션
   가구 형태(부부/개인) · 현재 나이 · 은퇴 나이 · 국민연금 예상액(공단 조회값, 개시연령)
   퇴직연금(적립금 또는 예상 월액) · 개인연금(예상 월액 또는 적립금)
   [고급] 목표 생활비 직접 입력 · 기대수명 · 실질수익률 · 은퇴까지 추가 납입
   ↓
[계산 엔진 호출] → 결과 JSON (가정값 버전 포함)
   ↓
[결과 카드]
   ① 월 연금 합계 (3층 막대)  ② 목표 생활비  ③ 월 부족액 · 총 부족액 · 매월 준비액
   ④ 국민연금 조기/정상/연기 비교표  ⑤ 은퇴 나이 시나리오표
   ↓
[AI 설명] "이 결과를 고객에게 어떻게 설명할까요?" / "62세로 당기면?" 등 what-if
   → what-if는 엔진 재호출, AI는 두 결과의 차이를 설명
   ↓
[저장] 고객 이름·메모와 함께 플랜 저장 → 이후 [내 플랜]에서 재조회·수정
```

입력 원칙
- 국민연금 예상액은 "공단 앱 또는 통합연금포털에서 확인한 월 예상액(현재가치)"임을 입력 필드에 명시한다.
- 값을 모르면 비워 두고 계산할 수 있다. 비어 있는 층은 결과 카드에 "미입력"으로 표시하고 AI가 확인을 권한다.

## 5. 계산 엔진 스펙

구현: 규칙 기반 순수 함수(TypeScript 또는 Python). 외부 호출 없음. 입력·가정값 버전·출력을 모두 JSON으로 주고받는다. 상속증여 Tax Engine, VFA 갭 엔진과 같은 구조.

### 5-1. 입력

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| household | `부부` / `개인` | 필수 | 생활비 기준 선택 |
| age | 정수 | 필수 | 현재 나이 |
| retire_age | 정수 | 필수 | 은퇴(연금 개시) 나이 |
| birth_year | 정수 | 필수 | 국민연금 정상 개시연령 판정용 |
| nps.monthly_base | 만원 | 선택 | 공단 조회 월 예상액 (정상 개시연령 기준, 현재가치) |
| nps.start_age | 정수 | 선택 | 국민연금 수령 시작 나이 (기본: 정상 개시연령) |
| retirement_pension | 객체 | 선택 | `{type: DC/IRP/DB, balance, annual_contrib}` 또는 `{monthly_expected}` |
| personal_pension[] | 배열 | 선택 | 각각 `{monthly_expected}` 또는 `{balance, annual_contrib}` |
| target_level | `적정` / `최소` | 선택 | 기본 `적정` |
| target_monthly | 만원 | 선택 | 직접 입력 시 패널조사 기준 대신 사용 |
| life_expectancy | 정수 | 선택 | 기본 90 |
| real_return | 소수 | 선택 | 실질 수익률(물가 차감), 기본 0.00 |
| assumptions_version | 문자열 | 선택 | 기본 최신 버전 |

### 5-2. 가정값 테이블 (assumptions v2026.09)

목표 생활비 (국민연금연구원 국민노후보장패널조사 10차, 2024, 만원/월)

| 구분 | 최소 | 적정 |
|---|---|---|
| 부부 | 216.6 | 298.1 |
| 개인 | 139.2 | 197.6 |

국민연금 정상 개시연령 (출생연도별)

| 출생연도 | 개시연령 |
|---|---|
| 1953~1956 | 61세 |
| 1957~1960 | 62세 |
| 1961~1964 | 63세 |
| 1965~1968 | 64세 |
| 1969 이후 | 65세 |

조기·연기 조정
- 조기 수령: 1개월당 0.5% 감액, 최대 60개월(30%)
- 연기 수령: 1개월당 0.6% 증액, 최대 60개월(36%)
- 조기 수령은 소득 요건이 있으므로 결과 카드에 "소득이 일정 기준을 넘으면 조기 수령이 제한됩니다" 고정 문구를 붙인다.

기타 기본값: 기대수명 90세, 실질 수익률 0%.

가정값은 연 1회(패널조사·생명표 발표 시) 갱신하고 버전을 올린다. 기존 플랜은 저장된 버전으로 재현되며, 재계산 시 최신 버전 적용 여부를 사용자가 선택한다.

### 5-3. 산식

```
정상개시연령 N = TABLE_NPS_AGE[birth_year]
m = (nps.start_age − N) × 12
국민연금 월액 = m < 0 ? base × (1 − 0.005 × min(−m, 60))
              : base × (1 + 0.006 × min(m, 60))

n = retire_age − age                     // 은퇴까지 남은 연수
Y = life_expectancy − retire_age         // 노후 기간(년)
r = real_return

적립금 은퇴시점 가치 FV = r == 0 ? B + C × n
                        : B × (1+r)^n + C × ((1+r)^n − 1) / r
적립금의 월 연금 환산 = r == 0 ? FV / (Y × 12)
                      : FV × i / (1 − (1+i)^(−Y×12)),  i = r / 12

월 연금 합계 = 국민연금 월액 + 퇴직연금 월액 + Σ 개인연금 월액
목표 생활비 = target_monthly ?? TABLE_COST[household][target_level]
월 부족액 = max(0, 목표 생활비 − 월 연금 합계)
총 부족액 = round(월 부족액 × 12 × Y)
준비 기간(월) = max(1, n × 12)
매월 준비액 = round(총 부족액 / 준비 기간)
```

원칙
- 모든 금액은 현재가치(실질) 기준이다. 물가 상승은 실질 수익률 가정에 녹인다. 결과 카드에 "현재 물가 기준 금액"이라고 표시한다.
- 국민연금 월액에는 실질 수익률을 적용하지 않는다(공단 값이 이미 물가연동 가정).
- 국민연금 수령 시작 나이가 은퇴 나이보다 늦으면 그 사이 기간은 국민연금 0으로 계산한 별도 행(브릿지 구간)을 결과에 포함한다.
- 금액 표기: 만원 단위, 억 단위 넘으면 "N억 M,MMM만원" (상속증여·VFA와 동일 규칙).

### 5-4. 검증 케이스 (테스트 코드 필수)

| 케이스 | 입력 | 기대 결과 |
|---|---|---|
| A. VFA 갭 엔진 재현 | 부부/적정, 45세, 65세 은퇴, 연금 합계 120, 기대수명 90, r=0 | 월 부족 178.1 → "178만원", 총 부족 53,430 → "5억 3,430만원", 매월 준비 222.6 → "223만원" |
| B. 국민연금 조기·연기 | base 100, 1969년 이후 출생(N=65) | 60세 70.0 / 62세 82.0 / 65세 100.0 / 70세 136.0 |
| C. 3층 합산 | 개인/적정, 45세, 65세 은퇴, 국민 100(65세), DC 적립금 8,000 추가납입 0, 개인연금 30, r=0 | DC 월 환산 26.67, 합계 156.67, 월 부족 40.93, 총 부족 12,280, 매월 준비 51.2 |
| D. 은퇴 앞당김 | C와 동일하되 은퇴 62세, 국민연금 62세 조기, 기대수명 92 | 국민 82.0, DC 환산 8,000/(30×12)=22.22, 합계 134.22, 월 부족 63.38, 총 부족 22,816, 매월 준비 111.8 |
| E. 실질수익률 적용 | 적립금 8,000, 연 추가납입 600, 20년, r=2%, 노후 25년 | FV 26,466.0, 월 환산 112.18 |
| F. 경계값 | 은퇴 나이 = 현재 나이 | 준비 기간 1개월, 매월 준비액 = 총 부족액 |
| G. 상한 | 조기 84개월 요청 | 60개월로 클램프, 감액 30% |

수치는 2026-09-04 파이썬 스크립트로 검산했다. 엔진 구현 후 같은 케이스로 단위 테스트를 작성한다.

## 6. AI 역할과 프롬프트 규칙

### 인텐트

| 인텐트 | 예시 | 처리 |
|---|---|---|
| `연금계산` | "부족액 계산해줘", "은퇴 62세로 바꾸면" | 입력 수집 → 엔진 Tool 호출 → 결과 설명 |
| `국민연금시점비교` | "국민연금 몇 살에 받는 게 좋아" | 엔진 시나리오 표 → 설명. 유불리 판단은 "손익분기 나이" 사실만 제시 |
| `연금개념` | "IRP랑 연금저축 차이", "연금소득세" | RAG (연금 도서·교육자료·법령) |
| `연금상품추천` | "45세 고객 60세 개시 연금상품" | 1차: 판매중 상품 마스터 없으면 차단 후 "FA 상담·상품비교 화면" 안내. 3차에서 개방 |
| `보험료` | "연금보험 월 보험료" | 기존 보험료 안내 제한 규칙 그대로 적용 |
| `플랜변경` | "은퇴 65세에서 62세로", "펀드 추천 주기 60일로" | 플랜 객체 갱신 → 재계산 → 변경 전후 비교 설명 |
| `플랜조회` | "지난번 김OO 고객 설계 보여줘" | 저장 플랜 조회 → 결과 카드 재표시 |

### 금지 규칙 (시스템 프롬프트)

1. 연금액·부족액·수익률·세액 등 숫자를 직접 계산하거나 추정하지 않는다. 반드시 엔진 결과만 인용한다.
2. 엔진 결과에 없는 숫자를 만들지 않는다. 사용자가 "대략"을 요구해도 엔진을 호출한다.
3. "유리하다·불리하다·추천한다" 판단 대신 "A 시점이 B 시점보다 월 N만원 많다" 사실을 말한다.
4. 과거 수익률·실적 수치를 먼저 언급하지 않는다. (VFA 규칙 승계)
5. 판매 여부가 확인되지 않은 상품명을 추천하지 않는다.
6. 세제는 "2026년 기준" 연도를 반드시 붙인다.

### 답변 형식

- 결과 카드 아래 3~5문장 설명. "한 줄 결론 → 근거 숫자 → 다음 행동 제안(입력 보완, 시나리오 비교)" 순서.
- 마지막에 고정 고지문(9절).

## 7. 데이터 모델

```
Plan
  plan_id, owner_fa_id, customer_ref(이름·메모, 주민번호 저장 금지)
  inputs (5-1 입력 JSON)
  assumptions_version
  outputs (5-5 출력 JSON)
  settings { rebalance_cycle_days: 90 }     // 3차 VFA 연동용, 1차는 저장만
  created_at, updated_at
  history[] { changed_at, changed_by(chat|screen), diff, outputs_before }
```

- 플랜은 설계사 계정에 귀속. 고객 모드(2차)는 공유 토큰으로 읽기 전용 접근.
- 마이데이터 연동(2차)은 `inputs`를 채우는 어댑터일 뿐, 스키마를 바꾸지 않는다. 연금 관련 항목(국민연금·퇴직연금·개인연금·연금보험)만 매핑하고 나머지는 전달하지 않는다. (8/27 회의)
- `history`가 있어야 8/31 회의의 "변경 요청을 어디서 받았는지, 저장된 결과를 어디서 다시 보는지"가 해결된다.

## 8. 화면 통합 (채팅 vs 결과 화면)

8/31 회의에서 미확정이었던 부분. 제안은 **하이브리드**다.

| 상황 | 채널 |
|---|---|
| 최초 입력 | 선택 화면(폼). 5개 필드를 대화로 받으면 턴이 길어지고 오입력이 늘어난다 |
| 결과 확인 | 결과 카드(채팅 안에 카드로 렌더링, 동일 카드를 [내 플랜] 화면에서 재표시) |
| 변경 | 둘 다. 채팅 "62세로 바꿔줘" → 엔진 재호출 후 카드 갱신. 카드의 연필 아이콘 → 폼 |
| 재조회 | [내 플랜] 목록 화면. 채팅에서 "지난 설계"로도 호출 가능 |

기술 확인 필요: 벨루가 채널 안에서 외부 계산 API를 Tool로 호출할 수 있는지. 불가하면 계산기 페이지에서 계산한 결과 JSON을 대화 컨텍스트로 주입하는 방식(상속증여 계산기 방식)으로 간다. 12절 참조.

## 9. 컴플라이언스

- 고정 고지문(모든 결과 카드·답변 하단): "본 계산은 입력하신 정보와 통계 가정에 따른 참고용 시뮬레이션이며, 투자자문·투자권유에 해당하지 않습니다. 실제 연금액은 공단·금융회사의 안내를 기준으로 하세요." → 망고 검수 후 필요 시 모모 에스컬레이션. VFA 심의필(iFA2026-02-0415) 문구를 최대한 재사용.
- 국민연금 조기 수령 안내에는 소득 요건 제한 문구를 붙인다.
- 상품 추천 인텐트는 1차에서 차단한다. 8/18 답변품질 시트에서 판매 종료 상품을 추천한 사례가 있으므로 판매중 마스터 없이는 열지 않는다.
- 보험료 금액은 기존 제한 규칙에 따라 노출하지 않는다.
- 플랜에 주민등록번호·계좌번호를 저장하지 않는다. 마이데이터 연동 시 연금 항목만 전달한다.

## 10. 품질 검증

1. **엔진 골든셋**: 5-4 케이스 7건으로 시작해 오픈 전 30건으로 확장(출생연도 경계, 미입력 층, 상한 클램프, r>0). CI에서 자동 실행.
2. **지식 RAG 평가셋**: 연금 개념 질문 30건(국민연금·퇴직연금·연금저축·세제·건보료)을 기대답변과 함께 답변품질 시트 형식으로 작성. 학습 자료는 드라이브의 연금·은퇴설계 도서와 영업1팀 국민연금 교육자료.
3. **AI 설명 검수**: 엔진 결과 10건에 대해 AI 설명이 숫자를 바꾸거나 추가하지 않는지 확인(숫자 일치율 100% 목표).
4. **설계사 파일럿**: 오픈 전 설계사 5명이 실제 고객 사례 3건씩 입력. 입력 소요 시간 5분 이내, "고객에게 바로 보여줄 수 있다" 응답 80% 이상을 기준으로 한다.
5. **운영**: 플랜별 assumptions_version 로그, 엔진 오류율, 상품추천 차단 발생 건수를 대시보드에 둔다.
