# 등록 비용 — 과금 단위는 약관 파일 수

**비용은 약관 파일 건수로 매겨진다.** 상품 단위도, 용량 단위도 아니다.
이 한 줄이 등록 전략을 정한다.

## 상품 하나가 파일 하나가 아니다

모홈 검색 결과에서 확인된 대로, 한 상품이 여러 파일로 갈린다.

```
무배당 변액연금보험동행(사망보장형-월납)              ← 파일 1
무배당 변액연금보험동행(고도재해장해보장형-일시납)      ← 파일 2
무배당 변액연금보험동행(고도재해장해보장형-월납)        ← 파일 3
무배당 변액연금보험 동행 Plus(월납)                  ← 파일 4
무배당 변액연금보험 동행 Plus(일시납)                 ← 파일 5
무배당 변액연금보험 동행 Plus(사망보장형-월납)         ← 파일 6
```

여기에 **개정 판**이 곱해진다.
`보장형태 × 납입방법 × 판` — 실손처럼 판이 150개를 넘으면 파일 수가 폭발한다.

**상품당 파일 수(배수)를 모르면 예산 계획이 서지 않는다.**
벤더에게 「동행」 하나의 실제 약관 목록만 받아도 배수가 나온다. 가장 먼저 받을 숫자다.

## 예산 200파일 — 상품 단위로 살 때

현재 시드(손보 91 + 생보 29 = 120개 상품) 기준.

| 상품당 파일 | 담을 상품 | 생보 | 손보 | 손보 계약 커버리지 |
| --- | --- | --- | --- | --- |
| 1건 | 120개 (전체) | 29 | 91 | 100% |
| 2건 | 100개 | 29 | 71 | 95.4% |
| 3건 | 66개 | 29 | 37 | 77.6% |
| 4건 | 50개 | 29 | 21 | 60.4% |
| **6건** | 33개 | 29 | **4** | **26.3%** |

배수 6이면 손해보험이 4개만 들어간다. 「동행」 화면이 이미 6개였다는 점을 생각하면
낙관할 수 없는 구간이다. **배수가 커질수록 상품 단위 구매는 급격히 나빠진다.**

## 예산 200파일 — 계약 단위로 살 때

보장분석이 지목한 계약은 **보장형태 · 납입방법 · 판이 이미 하나로 정해져 있다.**
그러므로 계약 하나에 필요한 파일은 **정확히 1건**이다. 배수가 붙지 않는다.

```
KB손보 · KB다이렉트플러스운전자보험(무배당)(24.10) · 2024.11 가입
        ↓
파일 1건
```

같은 계약을 여러 고객이 보유하면 파일 하나로 함께 덮인다.
따라서 상품 중복률이 높을수록 커버 범위가 넓어진다.

| 고객당 계약 | 상품 중복률 | 200파일로 커버되는 고객 |
| --- | --- | --- |
| 6건 | 0% | 약 33명 |
| 6건 | 50% | 약 66명 |
| 6건 | 70% | 약 111명 |

실제로는 인기 상품이 겹치므로 중복률이 상당히 높게 나올 것이다.
표본 보장분석을 몇십 건만 모아도 이 값이 측정된다.

## 두 방식의 차이

| | 상품 단위 구매 | 계약 단위 구매 |
| --- | --- | --- |
| 파일 수 | 상품 × **배수** | 계약 유형 × **1** |
| 사는 것 | 조회되지 않을 조합까지 함께 | 반드시 조회될 파일만 |
| 근거 | 판매 실적(추정) | 보유 계약(확정) |
| 과거 상품 | 실적 목록에 없어 누락 | 자연히 포함 |

**과금이 파일 단위라는 사실이 계약 단위 구매를 압도적으로 유리하게 만든다.**
상품 단위로 사면 배수만큼 낭비가 곱해지고, 그 낭비분은 FA가 묻지 않을 조합이다.

`docs/plan.md`의 「보장분석 먼저」 제안이 여기서 비용으로 뒷받침된다.

## 계산 도구

```python
from orca.pricing import estimate_by_product, estimate_by_contract, TermsPricing

pricing = TermsPricing(price_per_file=30000)      # 단가 확정 시

estimate_by_product(50, files_per_product=4, pricing=pricing)   # 상품 50개 → 200파일
estimate_by_contract(200, pricing=pricing)                      # 고유 약관 200건 → 200파일
```

`registration_plan(seeds, files_budget=200, files_per_product=...)`은
파일 예산을 상품 수로 환산해 등록 목록을 잡는다.

## 아직 모르는 값

계획을 확정하려면 벤더에게 세 가지를 받아야 한다.

1. **파일 1건당 단가** — 현재 미확정. 금액을 화면에 표시하지 않는 이유.
2. **상품당 파일 수(배수)** — 「동행」 하나의 약관 목록이면 충분하다.
3. **판도 파일 수에 포함되는가** — 개정 판마다 별도 파일이면 실손 계열은 사실상
   전량 등록이 불가능하다. 요청이 몰린 판만 부분 등록하는 전략으로 가야 한다.

3번이 특히 중요하다. 판이 파일 수에 곱해지는지 아닌지에 따라
실손·건강보험 계열의 등록 가능 여부가 갈린다.
