# 공시실에서 상품명 수집

벤더에 등록된 약관은 현재 목록(손보 91 + 생보 29)이 전부다.
그 밖의 상품은 **상품명만이라도 확보해 두는 것**이 이 문서의 목표다.

약관이 없어도 상품명이 있으면 되묻기가 성립하고, 등록 요청이 정확한 상품으로 쌓인다.
카탈로그(상품 마스터)와 벤더 인덱스는 이미 분리돼 있으므로
(`Product.indexed`) 수집한 상품명을 그대로 얹으면 된다.

```
공시실 수집 상품명  →  카탈로그 마스터 (되묻기 선택지, 「약관 준비중」 표시)
벤더 등록 약관      →  indexed=True    (실제 검색 · 답변 가능)
```

## 수집은 가능한가

가능하다. 근거는 제도에 있다.

보험사 상품공시는 임의 양식이 아니라 금융감독원 「보험업감독규정」 ·
「보험업감독업무시행세칙」과 생명보험협회 「생명보험 상품통일공시기준」에 따른
**의무 공시**다. 각 사가 공시실에 상품목록과 약관을 올리고, 양식이 통일돼 있다.
모홈 같은 서비스도 이 구조를 쓴다.

다만 **어떤 경로로 가져올지**에 따라 비용과 커버리지가 크게 달라진다.

## 세 가지 경로

| 경로 | 장점 | 단점 |
| --- | --- | --- |
| **협회 통합공시** (생명보험협회 · 손해보험협회) | 여러 회사를 한 곳에서. 수집기 2개면 끝 | 제공 범위가 협회 정책에 달림 |
| **각 보험사 공시실** | 원본 파일과 상세 정보 | 회사마다 구조가 달라 수집기 30여 개. 개편 때마다 깨짐 |
| **협회에 데이터 제공 요청** | 가장 안정적. 이용 조건이 명확해짐 | 협의 시간 필요 |

**권장 순서: 협회 통합공시로 시작하고, 병행해서 협회에 제공 방식을 문의한다.**

각 사 공시실을 30여 개 긁는 방식은 초기 구축보다 **유지보수에서 무너진다.**
사이트 개편 한 번에 수집기가 멈추고, 그 사실을 상품이 안 나올 때까지 모른다.

공공데이터포털에 협회가 참여하고 있으나, 조사 범위에서는
**약관 파일 자체를 제공하는 공개 API를 확인하지 못했다.**
(이 환경에서는 해당 사이트 접속이 차단돼 있어 페이지 구조를 직접 확인하지 못했다.
실제 수집기는 사이트를 열어 보고 작성해야 한다.)

## 무엇을 함께 가져와야 하는가

상품명만 가져오면 절반이다. 최소한 다음을 함께 받아야 한다.

| 항목 | 용도 | 필수 |
| --- | --- | --- |
| 업권 (생보 / 손보) | 필터 | ✅ |
| 보험사명 | 되묻기 1단계 | ✅ |
| 상품명 | 되묻기 2단계 | ✅ |
| **약관 시행일** | **가입 시점 → 판 특정** | ✅ |
| 약관 파일 URL | 등록 요청 시 원본 확보 | ✅ |
| 판매 시작 · 종료일 | 과거 계약 대응 | 권장 |
| 종별 | 후보 좁히기 | 권장 |

**시행일이 빠지면 수집의 의미가 절반으로 준다.** 보상은 계약 시점 약관을 따르는데,
시행일이 없으면 판을 특정할 수 없어 되묻기가 끝까지 진행되지 않는다.
모홈 화면이 상품명과 시행일(2026-07-01)을 함께 보여주는 것도 같은 이유다.

## 과거 상품이 진짜 관건이다

공시실은 **현재 판매 중인 상품**이 중심이다. 그런데 보상 질문은
이미 가입한 계약, 즉 **판매가 끝난 상품**에서 더 많이 나온다.

따라서 수집을 시작하기 전에 확인해야 할 것은 하나다.

> **판매 종료 상품의 약관이 어디까지, 얼마나 오래 조회되는가.**

여기가 비면 상품명을 아무리 많이 모아도 보상 질문의 상당수는 답할 수 없다.
협회 · 보험사에 확인이 필요하며, 확인 결과가 곧 서비스가 답할 수 있는 범위가 된다.

## 전량 수집하면 되묻기가 2단계가 된다

공시실 상품을 다 가져오면 카탈로그가 수천 건이 된다.
그 상태에서 상품 칩 8개만 잘라 보여주면 FA가 찾는 상품이 그 안에 없다.

그래서 후보가 임계치를 넘으면 **보험사부터 되묻는다**(`NextAction.ASK_INSURER`).

```
FA   : 음주운전 사고인데 보험금 나와요?
Orca : 어느 보험사 상품일까요?
       [삼성화재] [DB손보] [KB손보] [현대해상] …
FA   : DB손보
Orca : 어느 상품일까요?
       [참좋은운전자상해보험] [건강할때 가입하는 청춘어람플러스 종합보험] …
```

모홈 검색 화면이 `생명보험` → `메트라이프생명` → 검색어 순인 것과 같은 구조다.
상품이 많은 목록에서 이름만으로 좁히는 것은 원래 안 된다.

한 번 고른 보험사는 세션에 남으므로(`ConversationContext.insurer`)
같은 상담 안에서 다시 묻지 않는다. 상품을 먼저 특정하면 보험사는 자동으로 채워진다.

## 수집 이후

- **갱신 주기** — 약관 개정은 분기 시작일에 몰린다. 분기별 수집 + 월 1회 점검이면 충분하다.
- **신규 상품 감지** — 목록에 없던 상품이 나타나면 카탈로그에 추가한다.
  이때 자동으로 등록되는 것이 아니라 「약관 준비중」으로 들어간다.
- **이용 조건** — 수집 방식과 범위는 각 사 · 협회의 이용 조건을 확인하고 진행한다.
  GA 회원사 자격으로 데이터 제공을 요청할 수 있는지 함께 확인하는 것이 좋다.
