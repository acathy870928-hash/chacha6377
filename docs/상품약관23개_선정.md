# 상품약관 23개 선정 (벨루가 검증용 30개 중)

`표준약관 7개 + 최근 판매상품 약관 23개` 의 뒤쪽 23개입니다.
원본 판매 데이터(199개 상품 / 30개사)는 `input/sales.xlsx` 에 두며 저장소에는 커밋하지 않습니다.

## 선정 기준

1. **보종을 먼저 덮는다.** 각 보험사 1위 상품만 모으면 간편건강보험이 절반을 넘습니다.
   199개 중 건강 계열이 74개로 압도적이라 자연 발생하는 쏠림이고, 그대로 두면
   실손·운전자·치아·펫·어린이·재물 약관은 한 건도 검증하지 못합니다.
2. **정렬은 실적 단독이 아니라 실적 40% + 건수 60% 종합 점수.**
   시트는 월납실적 순이지만, 약관 질문의 빈도는 실적이 아니라 가입 건수를 따라갑니다.
   실적만 쓰면 2건짜리 고액 종신이 위로 오고(달러종신 776만원/2건), 건수 1위인
   `참좋은운전자상해보험`(40건)이 23위로 밀립니다. 챗봇 검증 목적에는 건수가 더 중요합니다.
3. **한 보험사 최대 N개.** 특정 회사의 약관 문체에 과적합되는 것을 막습니다.
4. 보종을 다 덮고 남는 자리는 종합 점수 상위로 채웁니다.

표준약관 7종이 생명/화재/자동차/질병상해/실손/해외여행실손/배상책임의 **공통 뼈대**를 담당하므로,
상품약관 23개는 표준약관이 못 잡는 **간편고지 조건(3.10.5·5.10.5·3.N.5 등), 특약, 감액·면책, 갱신**
같은 상품 고유 조항을 검증하는 역할을 맡습니다. 간편건강보험을 여러 개 넣은 것은 쏠림이 아니라
숫자 조건이 서로 다른 표본을 확보하기 위한 것입니다.

## 재현

```bash
.venv/bin/python tools/select_products.py input/sales.xlsx                    # 안 A
.venv/bin/python tools/select_products.py input/sales.xlsx --per-insurer 1    # 안 B
.venv/bin/python tools/select_products.py input/sales.xlsx --audit            # 보종 분류 전수 확인
```

`--audit` 으로 199개 전체의 보종 분류를 눈으로 검증할 수 있습니다. 분류가 틀린 건이 보이면
`tools/select_products.py` 의 `RULES` 를 고쳐 다시 돌리면 선정 결과가 그대로 갱신됩니다.
