# 데이터 요청 명세

> 챗봇 품질을 실제로 끌어올리는 데이터를 **우선순위 순으로** 정리했습니다.
> 각 항목에 "이 데이터가 없으면 지금 무엇이 추측 상태인가"를 명시했습니다.

---

## 우선순위 요약

| 순위 | 데이터 | 없을 때의 문제 | 최소 규모 |
| --- | --- | --- | --- |
| 🥇 1 | **상담 대화 로그 + 결과 라벨** | 반론·인텐트·톤이 전부 추측 | 500건 |
| 🥈 2 | **민원·불완전판매 사례** | 금지표현이 법령 역산 수준 | 20건 |
| 🥉 3 | **상품 데이터** | 상품 안내 자체가 불가 | 판매 상품 전체 |
| 4 | **계약 유지율 데이터** | 적합성 판단 근거 없음 | 2년치 |
| 5 | **고객 세그먼트 통계** | 세그먼트 5종이 가설 | 전체 |
| 6 | **디지털 채널 이탈 로그** | 이탈 지점이 추정 | 3개월치 |

## 🥇 1. 상담 대화 로그 + 결과 라벨

### 왜 1순위인가

현재 아래 자산이 **전부 창작물**입니다. 이 데이터가 들어오면 실측 기반으로 교체됩니다.

| 현재 상태 | 교체 후 |
| --- | --- |
| 반론 6종 (일반론 기반) | 실제 빈도순 반론 N종 |
| 인텐트 22종 (상상한 표현) | 실제 발화 분포 기반 인텐트 |
| 대표 발화 30종 (제 문체) | 전환된 상담사의 실제 문체 |
| 이탈 지점 (추정) | 실측 이탈 단계 |

### ⚠️ 결과 라벨이 핵심

로그만으로는 **"사람들이 이런 말을 한다"**까지만 알 수 있습니다.
**"무엇이 통했는지"**를 알려면 결과 라벨이 반드시 함께 와야 합니다.

라벨 없는 로그의 가치는 라벨 있는 로그의 **약 1/3** 수준입니다.

### 요청 형식

```jsonl
{"conversation_id":"C-00001","channel":"call","date":"2026-03-14","duration_sec":420,"customer":{"age_band":"35-39","gender":"M","income_band":"300_400","employment":"EMPLOYEE","household":"COUPLE_WITH_CHILD","owned_pension":["NPS","RETIREMENT_DC"]},"turns":[{"speaker":"agent","text":"안녕하세요, ..."},{"speaker":"customer","text":"지금은 좀 여유가 없어서요"},{"speaker":"agent","text":"..."}],"outcome":{"result":"CONVERTED","exit_stage":null,"product":"연금저축보험","monthly_premium":200000},"objections":["no_money","later"]}
```

### 필수 필드

| 필드 | 필수 | 설명 |
| --- | :---: | --- |
| `conversation_id` | ✅ | 비식별 ID |
| `turns[]` | ✅ | 발화 순서대로. `speaker`는 agent/customer |
| `outcome.result` | ✅ | `CONVERTED` / `BOOKED` / `MATERIAL_SENT` / `DROPPED` / `REJECTED` |
| `outcome.exit_stage` | ✅ | 이탈한 경우 어느 단계인지 (1~5) |
| `customer.age_band` | ⬜ | 5세 단위 구간 |
| `customer.income_band` | ⬜ | 구간값 |
| `customer.employment` | ⬜ | 세그먼트 분석에 중요 |
| `objections[]` | ⬜ | 이미 태깅되어 있다면 |

> `outcome.result`와 `exit_stage` 두 필드만으로도 분석의 80%가 가능합니다.
> 나머지가 없다면 이 둘만이라도 채워주세요.

### 규모

| 규모 | 가능한 분석 |
| --- | --- |
| 200건 | 반론 유형 도출 |
| 500건 | 반론별 대응 성공률 |
| 2,000건 | 세그먼트별 전략 실측 검증 |
| 5,000건+ | 인텐트 분류기 학습 |

### 🔒 비식별화 요청

전달 **전에** 아래를 제거하거나 마스킹해 주세요.

```
❌ 이름, 주민등록번호, 전화번호, 주소, 계좌번호
❌ 질병명·병력 등 건강정보 (민감정보)
❌ 특정 상담사 실명
✅ 나이 → 5세 구간으로 변환 (예: "35-39")
✅ 소득 → 구간으로 변환
✅ 금액 → 만 원 단위 반올림
```

원문 텍스트에 개인정보가 섞여 있으면 정규식 마스킹 후 전달을 권합니다.
비식별화가 어려우면 **텍스트 없이 메타데이터만**(반론 태그 + 결과 라벨) 주셔도 절반의 가치는 있습니다.

## 🥈 2. 민원·불완전판매 사례

### 왜 필요한가

현재 `forbidden-expressions.json`의 금지표현 16종은 **법령에서 역산**한 것입니다.
실제로 이 회사에서 무엇이 문제가 됐는지는 다를 수 있습니다.

> 민원 1건 = 제가 만든 규칙 1개보다 정확한 근거

### 요청 형식

```
| 사례ID | 발생연도 | 유형 | 문제된 표현·행위 | 처리 결과 | 재발방지 조치 |
|--------|---------|------|-----------------|----------|--------------|
| M-001  | 2024    | 불완전판매 | "원금 보장된다고 들었다" | 계약 취소 | 설명 확인서 강화 |
| M-002  | 2025    | 부당권유 | 거절 후 재연락 | 배상 | 재권유 금지 시스템화 |
```

### 특히 유용한 것

1. **"어떤 표현 때문에" 분쟁이 났는지** — 금지표현 리스트에 즉시 반영
2. **금감원 지적 사항 / 검사 결과** — 규제 당국의 실제 관심사
3. **광고심의 반려 사례** — 어떤 카피가 왜 반려됐는지
4. **취약소비자 관련 사례** — 고령자·저소득층 대상 판매 이슈

### 규모

20건이면 충분합니다. 유형별로 2~3건씩만 있어도 패턴이 나옵니다.

## 🥉 3. 상품 데이터

### 왜 3순위인가

없으면 챗봇이 **아예 동작하지 않는** 필수 자료입니다.
다만 판단이 필요 없이 "구해오면 되는" 자료라 우선순위상 3위입니다.

현재 `product-schema.json`의 상품 3종은 **예시 데이터**이며 `compliance_approved: false` 상태입니다.

### 요청 항목

| 항목 | 형식 | 우선순위 |
| --- | --- | --- |
| 판매 중인 연금 상품 리스트 | 표 | 필수 |
| 상품설명서 | PDF | 필수 |
| 약관 | PDF | 필수 |
| 상품별 스펙표 | XLSX | 필수 |
| **광고심의 통과 카피** | 문서 | ⭐ 강력 권장 |
| 상품별 예시 설계안 | PDF | 권장 |
| 판매 중지 예정 상품 목록 | 표 | 권장 |

> ⭐ **이미 심의를 통과한 카피**가 있으면 그대로 재활용할 수 있어 준법 검수 기간이 크게 단축됩니다. 이게 있고 없고가 Phase 5 소요 기간을 좌우합니다.

### 스펙표 필수 컬럼

`product-schema.json`의 필드와 1:1 대응합니다.

```
상품코드 | 상품명 | 세제구분 | 가입연령(최소/최대) | 납입기간 옵션 |
최소보험료 | 연금개시연령 옵션 | 수령형태 | 최저보증이율 |
세제혜택 유형 | 주요 위험 고지사항 | 판매상태 | 심의번호
```

## 4. 계약 유지율 데이터

### 왜 가입 데이터보다 중요한가

**어떤 고객이 중도 해지하는가 = 누구에게 팔면 안 되는가 = 적합성 원칙의 실측 근거**

무리하게 판 계약은 해지로 돌아와 고객·회사 모두 손해입니다.
이 데이터가 있으면 세그먼트별 **권장 납입액 상한**을 실제 수치로 조정할 수 있습니다.

### 요청 형식

```
| 세그먼트 | 평균 월납입액 | 13회차 유지율 | 25회차 유지율 | 평균 해지 시점 |
|---------|-------------|-------------|-------------|--------------|
| 30대 직장인 | 21만 원 | 88% | 76% | 19개월 |
| 자영업자   | 25만 원 | 79% | 61% | 14개월 |
```

납입액 구간별 유지율이 함께 있으면 더 좋습니다.

```
| 월납입액 구간 | 13회차 유지율 |
|-------------|-------------|
| 10만 원 이하 | 92% |
| 10~20만 원  | 87% |
| 20~30만 원  | 81% |
| 30만 원 초과 | 68% |   ← 이 지점이 "권하면 안 되는 선"
```

## 5. 고객 세그먼트 통계

### 현재 상태

`segment-playbook.md`의 세그먼트 5종은 **가설**입니다.
실제 고객 분포와 전환율로 검증·재분류가 필요합니다.

### 요청 형식

```
| 세그먼트 | 전체 대비 비중 | 상담 전환율 | 계약 전환율 | 평균 보험료 |
|---------|-------------|-----------|-----------|-----------|
| 2030 직장인 | 22% | 14% | 3.1% | 15만 원 |
| 3040 직장인 | 38% | 19% | 5.2% | 22만 원 |
```

### 이 데이터로 하는 것

- 세그먼트 재정의 (제 5종 분류가 맞는지 검증)
- 우선 공략 세그먼트 결정
- 세그먼트별 KPI 목표치 현실화 (현재 목표는 업계 추정치)

## 아무것도 준비 안 됐다면

**딱 두 개만 주셔도 시작할 수 있습니다.**

1. 상담 로그 200건 + `결과 라벨`(전환/이탈)
2. 판매 중인 상품 스펙표 1장

이 둘이면 반론 스크립트와 상품 KB를 실제 데이터로 교체할 수 있고,
그것만으로도 지금 상태 대비 품질이 크게 올라갑니다.
